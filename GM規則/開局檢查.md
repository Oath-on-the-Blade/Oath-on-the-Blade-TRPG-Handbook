# GM規則：開局檢查

本文件是《武與俠》角色及劇本進入受限主持階段前的權威檢查。它負責確認玩家與參與角色數量、逐人接收角色卡、核對角色卡完整性、重跑履歷、待處理更新、點數合法性、社會名譽、裝備攜帶、世界內連續性、隊伍配置與主持資料準備；不負責開局前環境設定、建立角色、劇本內主持、角色卡更新程序或結算。

- 開始本文件前，先依 `GM規則/開局環境.md` 完成 persistent storage 設定並取得已驗證的 `opening_environment`。
- 新角色建立見 `GM規則/創角.md`。
- 角色卡欄位與內部一致性見 `GM規則/角色卡格式.md`；既有角色卡的校正與待處理更新完成見 `GM規則/角色卡更新.md`。
- **正式開局資格檢查開始前，必須先依第 1.1 節提供一次開局前角色卡更新窗口。**
- 俠名、惡名、名氣與相對名譽的公式見 `遊玩規則/角色/社會名譽與門派.md`；正式相對名譽對象見 `內容庫/相對名譽對象.md`。
- 攜帶格與出發前整備見 `遊玩規則/系統與機制/裝備基礎.md`；劇本整備資料應已依 `劇本設計規則/整備設計.md` 完成。
- 通過本文件並進入劇本後，依 `GM規則/遊戲流程.md` 主持；社會名譽影響 NPC 的方式見 `GM規則/社會互動.md`。
- 終局交接後依 `GM規則/結算.md` 結算。

角色綁定一份**新劇本／新遊戲存檔前**，先完成第 1 節收卡與第 1.1 節更新窗口，再執行第 2 至 7 節正式資格檢查。續跑同一個尚未結算的遊戲不重新建立入場資格，也不視為重跑；沿用原本已保存的開局環境、玩家／角色名單、角色入場檢查與存檔命名空間，只按第 8 節重新載入最新存檔及主持上下文。

檢查期間只讀取玩家選定投入本局的角色卡、當前劇本、完成核對所需的正式規則及已驗證的開局環境。建立命名空間或續跑載入時，只可存取其明確指定的目標；不得在本文件內另選 storage、進行 Connector 教學，或搜尋、列舉及修改其他角色卡、其他遊戲存檔或無關 persistent storage。

## 確認玩家、角色數量與逐人上傳

讀取及核對任何角色卡之前，AI GM 先請 host 宣告並由聊天室成員確認：

- 預定玩家總數及每名玩家在聊天室中的可辨識名稱；
- 每名玩家預定操控的 PC 數量，以及本局參與 PC 總數；
- 玩家與角色的一對一或一對多對應；角色數量可以不同於玩家數量，但每名 PC 必須只有一名明確操控者；
- 所有預定玩家均已加入目前聊天室，能看到本局訊息並可自行回覆。

在共享聊天室中，AI GM 必須逐名要求每位玩家**親自在目前聊天室上傳自己預定操控之每張完整角色卡**。實際成功附加並可由 AI GM 讀取才算通過；口頭聲稱「可以上傳」、只貼摘要／截圖、host 代傳，或角色卡只存在於玩家私人 Library／私人聊天，均不能證明該玩家已完成本閘門。同一玩家操控多名 PC 時，由該玩家逐張上傳全部角色卡。

每次提交至少記錄：

- 提交玩家的聊天室身份；
- 角色識別與其預定操控者；
- 可用時的檔名、附件／檔案識別、版本或內容雜湊；
- 提交時間及 AI GM 已成功讀取完整內容的結果。

全部提交後，AI GM 在聊天室公開列出「玩家 → 角色」對應及總數，請各玩家確認自己的項目。只有下列條件全部成立，才保存已確認的玩家可見開局名單並進入第 1.1 節：

- 實際回覆的玩家數等於 host 宣告的玩家數；
- 每名玩家均至少成功上傳一張自己將操控的完整角色卡；
- 實際角色卡數等於宣告的參與 PC 數，沒有重複角色、無主角色、未列入名單的額外角色或仍未指定操控者的角色；
- 每名玩家已確認自己的角色對應，而 host 已確認最終參與名單。

開局名單至少保存宣告玩家數、宣告角色數、玩家身份清單、「玩家 → 角色」對應、每張卡的提交者與可用檔案識別、逐人確認結果，以及名單已確認狀態；不得把 GM 私密資訊寫入此玩家可見記錄。

若玩家尚未加入、不能在目前聊天室上傳、上傳者身份無法判定、角色卡建立／補全尚未完成，或人數及角色數仍不一致，名單維持待確認。AI GM 不進入第 1.1 節、不建立新遊戲存檔，並請 host 修正聊天室權限、改用能讓所有玩家上傳的共享介面，或先依 `GM規則/創角.md` 完成角色後再重新執行本節。

本節的角色卡上傳只為確認參與者及取得入場檢查輸入，不授予玩家 persistent game save 的讀寫權。反過來，`GM規則/開局環境.md` 已驗證可寫入存檔，也不能代替本節的逐人上傳與名單確認。

### 開局前角色卡更新窗口

開局名單確認且每張角色卡已成功讀取後，**正式執行第 2 節起的角色資格檢查之前**，GM／AI GM 必須逐名向角色操控玩家提供一次更新窗口。

對每張角色卡：

1. 只依角色卡「待處理更新」欄，分開列出「必須處理」與「容後處理」。不得先做完整開局合法性掃描，也不得為了找更新項目搜尋其他角色或其他遊戲存檔。
2. 若有任何「必須處理」，明確告知玩家：**若要用這名角色參加本局，必須先完成全部「必須處理」，才能進入第 2 節正式資格檢查。**
3. 玩家選擇現在處理時，離開本檢查流程，依 `GM規則/角色卡更新.md` 完成相應 transaction。若該待辦來自既有正式結算而需要版本化更新原憑證，使用 GM 目前可合法取得的結算紀錄／憑證定位；角色卡本身不需要保存遊戲流水號或憑證版本。若無法唯一定位，請玩家／host 提供對應結算憑證，不得猜測。
4. 更新完成後，玩家須重新提交／確認完整目前角色卡；GM 成功重新讀取後，以新版本取代本次檢查輸入。
5. 玩家不處理「必須處理」、處理失敗或仍有未完成「必須處理」時，該角色停在開局前階段；玩家可改用另一名合資格角色，但不得帶著「必須處理」進入第 2 節。
6. 「容後處理」另行詢問。玩家可以現在處理，也可以明確宣告容後；容後本身不阻擋進入第 2 節。
7. 若角色卡沒有任何待處理更新，只記「無待處理更新」，不要求玩家為形式作空白選擇。

此窗口不是免費重創／重配窗口。合法未分配外功點等明文可保留資源不屬待處理更新，不必在此詢問是否花費。

## 固定檢查輸入

先固定：

- 當前劇本的正式識別、名稱、版本／來源；
- 有效重跑政策：缺欄、值不明或舊劇本沒有欄位時固定為「每角色一次」；只有劇本明文且完整定義時才可用「可重覆」；
- 劇本建議玩家人數、建議等級、建議等級上限 **H**、歷練基準等級 **R**；
- 劇本宣告的連續性、承接來源及特殊開場狀態；
- 劇本出發前整備類型、安全空檔、開始位置、可正常取得補給、已知限制及整備期間會推進的期限／危機；
- 劇本會引用的正式相對名譽對象及社會名譽場景；
- 每張待核對角色卡的完整玩家可見內容。

不得先產生或綁定新的遊戲存檔，再以「已經開局」為由略過不合資格項目。

## 角色卡格式、角色狀態與持續資料

逐張依 `GM規則/角色卡格式.md` 核對格式與內部一致性，並確認：

- 角色卡不是缺頁、摘要或只含戰鬥數值的臨時版本；
- 等級、歷練、氣血上限、武學、裝備、銀兩、俠名、惡名、名氣、相對名譽、人情／恩義／仇怨／懸賞／債務／承諾、共有／暫管資產、長期狀態及江湖履歷均完整；
- 角色卡上的待處理更新只以中文列「必須處理／容後處理」，沒有為後端稽核額外抄寫遊戲流水號、憑證版本或英文機器欄位；
- 角色的攜帶格上限可由力量修正值核對；最近確認隨身配置、材料／消耗品數量、坐騎／車輛載物與留存位置完整，所有已用格均不超過相應上限；
- 「擁有」與「目前隨身」沒有混為一談；未隨身的物品有可重新取得的實際存放位置，不能在新局開始時憑角色卡庫存直接視為已在手上；
- `名氣總點數 = 俠名總點數 + 惡名總點數`，沒有獨立加減來源；俠名／惡名級別按正式 `c=2,k=4` 推導；
- 每個非 0 相對名譽對象都能在 `內容庫/相對名譽對象.md` 找到，淨點數與有號級別使用該對象正式 c；角色卡沒有自創相對名譽對象；
- 若角色卡仍只有舊制 `名望／聲譽／勢力關係／口碑`，而沒有正式可稽核 migration，標記為需要遊戲階段外校正；不得臨場猜測換算；
- 每套武學的具體來源、各來源傳承上限與有效／持有狀態、保留／可修上限、尚需前提、入門狀態及未完成修習段均完整；
- 角色目前狀態容許投入遊戲；死亡、退休、永久留置或其他明確不可用狀態沒有被忽略；
- 既有角色的合法資料沒有因換劇本而被重置、重配、清空或按劇本建議等級升降；
- 江湖履歷與目前持續狀態只含玩家可見資料，沒有 GM 私密真相。

發現格式缺漏或彼此矛盾時，先在受限遊戲階段外依 `GM規則/角色卡更新.md` 分類及修正：只有可由正式來源唯一核對的項目才可更新；來源不足時標記阻擋，不得猜測填補。更新完成後必須重新提交／讀取完整角色卡，再從本節重新核對；未完成前不能通過本閘門。

## 重跑履歷檢查

對每名 PC 執行完整履歷核對：

1. 讀取當前劇本的正式名稱、版本／來源、可用的正式劇本識別與有效重跑政策。
2. 掃描該角色**全部江湖履歷**，以角色卡保存的劇本正式名稱、版本／來源及「劇本識別」（若有）比對相同劇本；完成、失敗、任務放棄、提前撤離及 0 歷練紀錄都算正式紀錄。角色卡不需要保存每局遊戲流水號。
3. 舊履歷缺少正式劇本識別時，以原記錄的正式劇本名稱、版本／來源或檔案識別作可稽核比對。能唯一對應當前劇本時視為相同；不能唯一判定時標記「需人工核對」，不得默認為沒有玩過，也不得靜默改寫舊履歷。
4. 有效政策為「每角色一次」時，只要存在一筆相同劇本的正式履歷，該角色即不合資格。新版本、新遊戲存檔、上次失敗／放棄／撤離或沒有取得歷練都不會重置資格。
5. 有效政策為「可重覆」時，確認劇本同時寫明事件為何可再次發生、每次如何成為不同事件，以及歷練、物品、俠名、惡名、每個相對名譽對象與其他後果的可重複範圍及上限；任何一項缺失便回落「每角色一次」。若定義完整，再依所有既有同劇本履歷核對既有次數／總量與剩餘上限。

重跑限制按**角色**計算，不按玩家計算。同一玩家可改用另一名通過檢查的角色；玩家若已有劇情知識，仍須向 GM 說明並把玩家知識與角色知識分開。

## 待處理更新與成長合法性

第 1.1 節已先清除所有「必須處理」；本節確認角色卡在目前版本沒有新的入場阻擋成長問題。

逐名檢查：

- 角色卡沒有任何仍未完成的「必須處理」；
- 「容後處理」可以繼續保留，單純存在不造成阻擋；
- GM／AI GM 沒有代玩家選擇或代擲；若玩家此時才決定完成待辦，仍須退出本檢查流程，依 `GM規則/角色卡更新.md` 更新完整角色卡，再從相應檢查點重新核對；
- 外功等可保留點數的「逐項已投入總和 + 未分配 = 累積取得」，未分配不為負，投入符合學習來源、時點、資格、解鎖條件及單套 20 級上限；
- 每套武學的實際／有效等級不超過其可修上限；尚未完成入門或仍缺前提的武學不得列作已掌握或使用；
- 合法未分配外功點可以繼續保留，不視為未完成升級，也不要求為開局而全部投入；
- 發現違法超配時只依 `GM規則/角色卡更新.md` 校正不合法部分，不得藉校正免費重分原本合法投入。

任何仍存在的「必須處理」或不能核對的違法配置都會阻擋角色入場；「容後處理」與合法未分配點數不會阻擋。

## 連續性、任務配置與強度

只按遊戲世界內關係確定本局連續性：

- **連續**：只有戰役續章、緊接後傳或其他世界內直接連續運行才使用；核對合法連續交接的來源及帶入氣血、氣血骰、功力、武勢、短期狀態與消耗資源；
- **獨立**：未明列時的預設；不帶入前局場景／戰鬥短期耗損，但保留已消耗或失去的物品、長期傷患、俠名、惡名、名氣、相對名譽、人情／恩義／仇怨／懸賞／債務／承諾、銀兩及其他持續後果。

玩家在現實中立即連玩、隔日或相隔數月都不會自行改變連續性，也不構成世界內休息。

完成持續狀態核對後，角色依外功規則選定本次任務的主外功與次外功並計算次外功有效等級；這是任務配置，不是重分實際外功等級。GM 再按實際隊伍調整敵人數量、層級、首領模板、危機速度與內容壓力。

臨場增減敵人數量、氣血、AC、DC 或危機速度不會自動改變結算用 **H**。只有開局前已把整份劇本的對手層級、資源壓力、局勢複雜度、風險、可承擔後果與獎勵實質重新校準為另一正式等級版本，並記錄新的建議等級／H、R 與相應基礎歷練，才使用新版數值。

## 檢查結果與新遊戲綁定

為每名 PC 產生玩家可見的角色入場檢查，至少包含：

- 角色識別、提交玩家、預定操控者、核對時間及角色卡可用版本標記（若儲存格式提供）；
- 當前劇本識別／版本及有效重跑政策；
- 匹配履歷數量與重跑判定；可重覆時另列既有次數／總量及本次適用上限；
- 第 1.1 節更新窗口的玩家宣告結果，以及「必須處理／容後處理」核對結果、可保留點數帳及機制合法性；
- 攜帶格上限、最近確認已用格、坐騎／車輛載物及留存位置的核對結果；
- 俠名、惡名、名氣與會在本劇本引用的相對名譽對象之核對結果；
- 角色可用狀態、武學來源／上限／修習狀態、本次主／次外功配置；
- 連續性、承接來源與實際帶入狀態；
- 最終結果：合資格或阻擋，以及具體理由。

只有開局名單已確認，且所有預定 PC 均為合資格，或不合資格角色已被正式移出名單／由原操控玩家重新上傳另一名合資格角色並再次確認名單後，才建立新的遊戲識別與存檔。同一劇本另開一桌使用另一個新遊戲識別，但新識別不會改變任何角色的重跑資格。

建立新遊戲存檔時，只使用 `GM規則/開局環境.md` 已交付且驗證成功的開局環境，依其 storage backend、target 與 save namespace 策略建立可寫入及重新讀取的專用命名空間；GitHub 方案此時才建立本局臨時 branch，ChatGPT Library 方案此時才建立本局穩定 Library save 項目或可稽核版本鏈。初始存檔保存開局環境、玩家／角色名單、劇本識別／版本、H、R、重跑政策、連續性、整備窗口資料、通過檢查的角色快照及全部角色入場檢查，並完成一次寫入後重新讀取驗證。若驗證失敗，不得在本文件內另選 storage 或進行設定教學；停止開局並返回 `GM規則/開局環境.md`，待 host 修正或另選合法方案後重新開始本節。
