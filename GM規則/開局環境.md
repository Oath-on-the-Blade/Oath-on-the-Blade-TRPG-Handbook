# GM規則：開局前環境設定

本文件是《武與俠》AI GM 在開局檢查之前設定 persistent storage 的權威流程。它只負責選定、教學、授權確認及驗證 game save 環境，以及確認結算產物的玩家下載方式，並產出可交給 `GM規則/開局檢查.md` 的 `opening_environment`；不讀取角色卡、不核對重跑履歷、不配置劇本，也不建立新 `game_id`。

- 新角色建立見 `GM規則/創角.md`。
- 角色卡、履歷、成長與入場資格見 `GM規則/開局檢查.md`。
- 已建立遊戲的存檔更新與續跑見 `GM規則/遊戲流程.md`。
- 終局後的憑證、角色卡寫回及 storage 清理見 `GM規則/結算.md`。

新遊戲必須先完成本文件，再進入開局檢查。續跑同一個尚未結算的 `game_id` 時，不重新選擇 backend；只重新載入原本保存的 `opening_environment`，確認原 target 仍可用，再由 `GM規則/遊戲流程.md` 從原 namespace 載入存檔。需要遷移時，由 host 在受限遊戲階段外另行決定及執行。

環境設定期間不得讀取玩家角色卡、劇本內容、其他 `game_id` 或無關 persistent storage。只有 host 明確指定的連接與 target 可以用於必要的存取及驗證。

---

## 固定設定或詢問 host

若 Instruction、宿主系統設定或 host 已經固定指定 storage backend、確切 target、save namespace 規則、存取邊界及玩家下載方式，AI GM 使用該設定，不重複要求 host 選擇；但仍須確認該 target 可合法讀寫。只指定「使用 Google Drive／GitHub／ChatGPT Library」而沒有資料夾、repo、Library 位置、`player_delivery_method` 或其他必要 target，不算完整設定，須詢問缺少的資料。

若 Instruction 沒有固定 persistent storage，AI GM **首先詢問 host 採用哪種儲存方案**，不得因環境剛好連接某項工具便自行選擇。可使用以下提示：

> 目前 Instruction 未固定 game save 的 persistent storage。請 host 選擇：Google Drive、GitHub、ChatGPT Library（如目前帳號／工作區可用），或其他類近的持久化方案。若選 Google Drive，是否需要進入指定資料夾？若選 GitHub，請指定一個 repo；角色通過開局檢查並建立 `game_id` 後，會在該 repo 建立本局專用臨時 branch 保存 game save。若選 ChatGPT Library，請確認 Library 已啟用，並指定私人檔案位置或資料夾（如介面支援）。若選其他方案，請提供確切 target 與存取方式。

host 尚未選擇時停在本節，不進入角色卡或劇本檢查。

## 詢問是否需要詳細設定教學

選定方案後，若環境尚未設定或尚未證明可用，AI GM 必須向 host 或由 host 指定負責設定的玩家詢問：

> 你是否需要我提供詳細的環境設定教學？我可以按你目前使用的宿主介面，逐步說明如何安裝／連接／啟用所需 Connector、準備 Google Drive 資料夾、建立並授權 GitHub repo，或確認 ChatGPT Library 可用性與權限等步驟。

玩家需要詳細教學時，AI GM 按實際選擇逐步教導：

1. 先確認玩家正在使用的宿主產品／介面、可用 Connector／App，以及哪些步驟必須由玩家手動完成；介面名稱不確定時先詢問或依當前正式介面指引，不虛構按鈕或聲稱已替玩家完成登入。
2. 教導玩家在宿主的連接／Connector／App 設定中找到、安裝（如需要）、啟用並連接所選服務，完成服務端登入，只授予 game save 所需的最低權限。玩家自行處理登入與授權，不在對話中提供密碼、token、復原碼或其他憑證。
3. 依方案準備 target：Google Drive 建立或選定專用資料夾並確認是否需要 AI GM 進入；GitHub 建立或選定一個 host 授權、宜為私人且專用的 repo，確認 Connector 可讀寫該 repo 及建立 branch；ChatGPT Library 先確認目前帳號／工作區確實提供 Library、AI GM 獲准建立與重新讀取檔案，並選定 host 私人位置或資料夾（如介面支援）；其他方案則建立可隔離各局遊戲的 project／container／folder／namespace。
4. 請 host 回報確切 target，並教導其確認連接範圍、寫入權限、重新讀取、更新／版本／衝突控制及結算後政策。必要時只在 host 指定 target 內使用不含 GM 秘密的測試資料作一次「建立 → 重新讀取 → 更新或建立下一版本 → 再次讀取」驗證。
5. 另請 host 確認結算後以何種方式向玩家提供可下載的完整角色卡與 `settlement_receipt`。該 `player_delivery_target` 可以與 GM 私密 game save 使用同一服務，但必須是分開的玩家可見檔案／位置及權限；不得為了交付而開放 GM 私密 save。
6. 教學、玩家手動設定及驗證全部完成後才繼續；若仍不可用，說明卡在哪一步並繼續協助，不跳過 persistent storage 或玩家下載交付要求。

若玩家表示不需要詳細教學，記錄為 `declined`，由 host 直接提供已準備好的 target；之後驗證失敗時可再次詢問是否需要教學。Instruction／宿主已提供且驗證完成的固定環境可記為 `not_needed`，不重複教學。

## 各儲存方案的最低要求

- **Google Drive／GDrive**：詢問是否需要進入指定資料夾；需要時由 host 指定確切資料夾，不需要時亦由 host 確認可用位置。只在該位置建立遊戲專用 save namespace，不搜尋或列舉其他 Drive 內容。
- **GitHub**：由 host 指定確切 `owner/repo`，以及必要時指定允許的 base branch 或 branch 命名規則。日後每個通過開局檢查的新 `game_id` 使用專用臨時 branch，例如 `gamesave/<game_id>`；不得直接把動態存檔寫入 default branch，也不得瀏覽或修改其他 branch／repo 內容。結算後按 host 的保留、封存或清理政策處理臨時 branch。
- **ChatGPT Library**：只有在目前 host 帳號／工作區確實提供 Library，且 AI GM 獲准建立、重新讀取及更新檔案時才可選用。host 指定私人 Library 位置或資料夾（如介面支援）；每局使用穩定檔案識別，例如 `OOTB_Save_<game_id>.json`，更新同一檔案或建立具有唯一最新指標的可稽核版本鏈，不得每次建立無法判定先後的同名副本。ChatGPT 的普通上傳附件、對話生成檔預覽、暫存沙盒檔案或短效下載 URL，若未明確保存為 Library 項目，均不算 persistent save。若 Library 不可用、只讀、不能更新／版本化或不能重新讀取，便改請 host 選用其他方案。
- **其他類近方案**：由 host 指定服務／系統、確切 project／container／folder／namespace、讀寫方式、版本或衝突控制、存取邊界及結算後處理政策。該方案必須能持久寫入、重新讀取並隔離每個 `game_id`。

AI GM 只要求 host 選擇已獲授權的連接與 target，不要求在對話中貼上任何憑證。公共 repo、公共聊天室或玩家可直接看到且會洩露 GM 私密狀態的位置，不是合法 game save target。

進行中 game save 與玩家交付產物是兩種不同權限的資料。前者預設為 host／GM 私密；後者只包含 `GM規則/結算.md` 允許公開的完整角色卡及玩家可見憑證。若兩者使用同一 backend，仍須使用不同檔案／namespace 及存取範圍。`player_delivery_method` 記錄附件、分享或下載方式；`player_delivery_target` 記錄正式產物的穩定持久位置。可使用玩家獲授權的 Library／Drive 位置、repo artifact 或其他可重新取得的方式；對話中的可下載檔案可作交付入口，但若本身不是持久項目，仍須另有正式持久 target。短效下載 URL 只可作傳輸入口，不能取代正式檔案的穩定識別與持久位置。

## 驗證與 `opening_environment` 輸出

在不讀角色卡或劇本的前提下，確認：

- 所選 Connector／App 已由玩家完成必要登入與授權；
- AI GM 只能定位 host 指定的 target，不需要搜尋整個 Drive、GitHub 帳戶或其他 storage；
- target 支援持久寫入、重新讀取及適用的版本／衝突控制；
- ChatGPT Library 方案已確認 Library 對目前帳號／工作區可用，並通過建立、讀取及更新／版本化測試；不是只把檔案附加在當前對話；
- namespace 策略可以把不同 `game_id` 隔離；GitHub 方案確認可在指定 repo 建立專用臨時 branch；
- GM 私密 save 與玩家交付位置的權限已分離，且預定 `player_delivery_method` 可以在結算時產出玩家真正可下載及重新開啟的檔案；
- host 已指定結算後保留、封存或清理政策；
- 必要的測試資料不含角色、劇本或 GM 私密資訊，驗證後依 host 指示移除或保留為明確的 setup probe。

完成後保存一份不含憑證的 `opening_environment`，至少包含：

- `storage_backend`；
- `storage_target`；
- `save_namespace_strategy`；
- `player_delivery_method` 及 `player_delivery_target`；
- `setup_tutorial_status`：`completed`、`declined` 或 `not_needed`；
- `environment_verified: true` 及驗證時間／方式；
- 可用的版本／衝突控制；
- host 指定的 `storage_cleanup_policy`；
- 已批准的存取邊界。

若 target 不能持久寫入、重新讀取或隔離 `game_id`，不得輸出已驗證設定，也不得以聊天上下文冒充存檔。先讓 host 修正或另選方案。

---

## 交入開局檢查

本文件只交付 `environment_verified: true` 的 `opening_environment`，不自行建立角色、綁定劇本或產生 `game_id`。接著才進入 `GM規則/開局檢查.md`。

開局檢查確認所有 PC 合資格並產生新 `game_id` 後，才依 `save_namespace_strategy` 建立實際 namespace；GitHub 方案亦在該時點才建立 `gamesave/<game_id>` 臨時 branch，ChatGPT Library 方案亦在該時點才建立本局穩定 save 項目或版本鏈。初始存檔完成一次寫入後重新讀取驗證，才可進入 `GM規則/遊戲流程.md`。
