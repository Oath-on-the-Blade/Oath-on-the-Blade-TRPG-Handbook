# 劇本設計規則

本目錄規範如何製作一份可直接交給 GM 運行的《武與俠》TRPG 劇本，並把「創作」與「驗收」分成兩個工作階段。

## 戰役總劇本／階段劇本路由

若工作目標是**完整創作一整條連續戰役（總綱＋全部階段）**，在以下總綱／階段規則之外，必須完整讀取並遵守：

- [`戰役劇本師規則.md`](戰役劇本師規則.md)

完整戰役的作者流程固定為：

1. 先寫戰役總綱，並以 `戰役總劇本檢查.md` 通過總綱獨立反交付閘門；
2. 再按總綱寫完全部階段；若寫作中需要新的戰役級 NPC 佔位符、跨篇 state 或主要因果，先同步加回總綱、更新版本並重新通過總綱閘門；每一階段仍各自通過一般 Phase B；
3. 全部階段完成後，拿**最終總綱＋第一篇至末篇全部最終階段 md**一起執行 [`戰役整體覆檢.md`](戰役整體覆檢.md)，檢查跨篇身份／state／因果一致性，並針對關鍵人物與物品／證物的預期外狀態補合理 GM 回歸代用品或提早分支結局。

`戰役整體覆檢.md` 不取代總綱檢查或任何單篇 Phase B；它只在完整戰役全部階段完成後，追加一層跨篇整體韌性閘門。

若工作目標是建立、重整或擴張一個**連續戰役本身**，先把戰役視為位於各篇章之上的「總劇本」，並在一般 Phase A 共通讀取之外，完整讀取：

- [`戰役總劇本設計.md`](戰役總劇本設計.md)

戰役總劇本正式檔名前綴為：

- `OOTB_戰役總劇本_<戰役名>.md`

完成戰役總劇本初稿後，**只拿最終戰役總劇本 md**，另讀並執行：

- [`戰役總劇本檢查.md`](戰役總劇本檢查.md)

戰役總劇本有自己的反交付閘門；**不使用一般 `檢查.md` 的「可直接跑團單篇」標準驗收，也不跑拿手／社會名譽／整備等單篇運行檢查。**

若工作目標是撰寫、修訂或續寫某一個**戰役階段／篇章劇本**，則：

1. 先讀目前有效的戰役總劇本，取得跨篇世界真相、戰役級 NPC registry、campaign state、篇章接口及承接邊界；
2. 若寫作中發現需要新的戰役級 NPC 佔位符，先回總綱分配並更新總綱，不得在階段自行建立新的戰役主鍵；
3. 再按下方一般 Phase A 完成該篇可直接跑團的全部運行資料；
4. 完成後完全回到一般 Phase B：`檢查.md → 拿手檢查.md → 社會名譽檢查.md → 整備檢查.md → 實際觸發的專項檢查`。

正式階段劇本檔名前綴為：

- `OOTB_戰役任務_<戰役名>(<序號>)_<篇名>.md`

**戰役總劇本檢查不得替階段劇本代檢；階段劇本也不得因已存在總劇本而省略任何一般劇本運行資料。**

戰役階段在實際遊玩後的 `campaign_save` 生成、GM 私密交付、例外資料、版本化與下一階段重新載入，不屬劇本作者交付；其運行權威見 `GM規則/戰役存檔.md` 與 `GM規則/結算.md`。

## Phase A：設計

先完整讀取：
- [`設計.md`](設計.md)
- [`世界知識使用.md`](世界知識使用.md)
- [`社會名譽設計.md`](社會名譽設計.md)
- [`整備設計.md`](整備設計.md)

並讀取共用世界基準：
- `世界知識庫/README.md`
- `世界知識庫/地理與世界基準/時代與世界基準.md`
- 本劇本涉及的其他 `世界知識庫/` 分類文件；凡使用固定地區、門派、朝廷人物、名宿、商號、綠林或歷史關係，都必須讀其權威條目

`世界知識使用.md` 是所有正式劇本共通規格。它規範共用正典、局部真相、刻意未知、隱藏母勢力、地理路程、角色知識與戰役連續性；`世界知識庫/` 本身只保存世界事實，不承載劇本設計、GM 主持或遊戲機械指引。

`社會名譽設計.md` 是所有正式劇本共通規格。即使某份劇本不預定給予俠名、惡名或相對名譽，也必須確認既有角色的名氣／名譽是否會合理影響 NPC；若確實完全無關，正文可明寫無社會名譽變化／無名譽門檻。劇本不得沿用舊制 `名望／聲譽／勢力關係／口碑 +1`，亦不得自行建立新的相對名譽對象。

`整備設計.md` 也是所有正式劇本共通規格。每份最終劇本都必須提供可直接執行的出發前整備窗口、確切安全空檔與角色可知補給資訊；一般、連續、突發或自訂整備均不得留給 GM 臨場猜測。0 小時突發開場只能確認當下實際攜帶，不能免費追溯購物、取物、補水、製作或休息。

若當前劇本宣告與任何已完成劇本存在前傳、後傳、平行、承接、共享事件、揭曉或其他明確跨劇本關連，必須再完整讀取：
- [`跨劇本關連設計.md`](跨劇本關連設計.md)

`跨劇本關連設計.md` 是一般劇本跨篇關連的**專項補充規格**。單一延伸完全合法；硬性要求是先找出來源所在的完整關連 component 並保持整體自洽。根任務在**第一個關連任務建立時**才建立 `_任務_<根任務名>_關連樹目錄/`；之後沿用穩定歸檔根。若一份關連任務實質同時承接另一棵樹，只在該任務列明跨樹直接關連，不合併兩棵樹、不複製劇本、不因跨樹而改根。

若打算把劇本設計成、或最終規格頭明列：
- `運行類別：可重覆任務`

則必須再完整讀取：
- [`可重覆任務設計.md`](可重覆任務設計.md)

若**當前劇本本身不是可重覆任務，但與一份可重覆任務宣告前傳、後傳、平行、承接、前置或其他跨劇本關連**，仍必須讀取：
- [`可重覆任務設計.md`](可重覆任務設計.md) 的 **4.1「跨劇本前置隔離」**。

此時只因「跨劇本關連」而觸發的部分，不會把當前一般劇本自動變成可重覆任務；但**不得把可重覆任務作必要前置基礎**的規則仍是硬性規格。

若劇本任何必要線索、真相、文書或姓名機關依賴漢字字形、拆字、形近字、姓名文字、同音／近音、諧音、口音、聲調或誤聽，則必須再完整讀取：
- [`文字機關設計.md`](文字機關設計.md)

若劇本把任何正式門派的 `〈門派〉引薦` 列為可取得獎勵，必須再完整讀取：
- [`入門引薦設計.md`](入門引薦設計.md)

此類正式稱為**入門引薦委託**，規格頭應明列 `任務類別：入門引薦委託（非門派專用任務）`。**單純提供入門引薦不會把劇本變成門派專用任務，也不會單獨觸發門派武學設計。** 引薦必須只是至少兩項個人可選獎勵之一；未入門角色可正常完成核心事件，已是門人或已有同派有效引薦者改選另一項既定獎勵。

若劇本出現以下任一情況，必須再完整讀取：
- 劇本本身是**門派專用任務**；
- 劇本會給予或提高任何 `[來自〈門派〉]` 的武學來源／解鎖上限；
- 劇本會讓門派外角色取得具名門派武學的無標籤來源；
- 劇本的重要 NPC 會向門派外角色教授其本門武學。

此時讀取：
- [`門派武學設計.md`](門派武學設計.md)

若同一劇本同時觸發多個專項模組，全部同時適用。`跨劇本關連設計.md` 不會把一般關連樹升格成戰役，也不會放寬可重覆任務的跨劇本前置隔離；`文字機關設計.md` 只在**姓名欄位為已預寫文字機關不可替代資料**時，提供「最小固定姓名欄位」窄範圍例外；可重覆任務的事件重現、`LOC#`、`PROP#`／`CLUE#`、新 `game_id` 新人物、`variant_id`、獎勵上限及跨劇本前置隔離不因此放寬。門派武學設計亦不會取代可重覆任務或社會名譽規則；例如可重覆門派任務仍必須同時遵守兩套模組。入門引薦委託若另外真正授予門派武學，則同時觸發入門引薦與門派武學兩套專項規格。

再按需要查閱：
- `世界知識庫/`；共用地理、歷史、固定人物、門派首領、外號與武學源流不得由單一劇本擅自改寫，具體使用邊界依 `世界知識使用.md`
- `遊玩規則/`
- `內容庫/`；若涉及社會名譽，正式相對名譽對象必須查 `內容庫/相對名譽對象.md`
- 若需要理解 GM 如何在實際遊戲中處理某種資料，再讀 `GM規則/README.md` 及其指定子文件；社會互動另讀 `GM規則/社會互動.md`；可重覆任務另須遵守 `GM規則/可重覆任務.md`；文字機關另須遵守 `GM規則/文字機關.md`。

設計階段負責：在世界知識庫的共用起始基準內建立本劇本局部世界真相、交付形式、規格頭、時間線、NPC、跨劇本關係、線索、場景、遭遇、危機、出發前整備、獎勵、歷練、俠名／惡名／名氣／相對名譽、終局、偏離處理及可直接運行的細節。

`世界知識使用.md` 是所有劇本的**共通正典使用規格**；世界知識庫明列的世界事實不可被單一劇本無限定改寫，劇本新增的地方單位、秘密隸屬與局部歷史必須能和共用基準並存。

`社會名譽設計.md` 是所有劇本的**共通社會系統規格**；俠名與惡名以本次實得基礎歷練倍率增加、名氣由兩者總和推導、相對名譽只可引用 Handbook 已登錄對象。劇本若需要新勢力／大類，必須先修 Handbook，不得把新數值藏在單一劇本。

`整備設計.md` 是所有劇本的**共通出發前資源規格**；它要求整備窗口與連續性、突發因果、世界時間、已知行程、食水／補給、攜帶與留存真正接入劇本正文，而不是只存在於遊玩規則。

`跨劇本關連設計.md` 是所有明確前傳／後傳／平行／承接／共享事件等跨劇本關連的**專項補充規格**；它要求第一個關連任務才建立根任務關連樹目錄、每個任務只有一個主要歸檔樹、跨樹只建立任務指向，以及所有新節點對完整 component 的既有客觀事實與 branch state 保持自洽。

`可重覆任務設計.md` 是該運行類別的**加嚴補充規格**；一般劇本不因規模小、NPC 名稱可變、地點可變、關鍵道具／線索表象可變或情節簡單而自動取得重跑資格。可重覆任務除了 NPC／LOC 外，關鍵 `PROP#`／`CLUE#` 的**非必要固定形態**也須在新 `game_id` 重新實例化；若形態會改變機械或因果，必須預寫差異或升格成 `variant_id`。

`文字機關設計.md` 是所有使用必要文字／讀音機關劇本的**專項補充規格**。凡依賴讀音推理，最低必須考慮普通話／國語與粵語使用者；不能把只在普通話成立的諧音當成唯一通關鑰匙而沒有粵語平行提示或非讀音冗餘路徑。

`入門引薦設計.md` 是所有把 `〈門派〉引薦` 作為可取得獎勵劇本的**專項補充規格**。它把此類劇本正式定義為一般任務中的「入門引薦委託」，要求引薦只是可選獎勵之一、由有權人物／制度具名背書、不能轉讓或疊加，而且取得引薦不等於入門、不自動給門派聲譽或武學。

`門派武學設計.md` 是所有門派專用任務、門派武學正式授權及門派武學外流劇本的**專項補充規格**。它要求門派正式來源帶 `[來自〈門派〉]` 標籤、依任務等級使用正式解鎖節點、門派外來源保持獨立無標籤，以及現役門人不把本門武學當一般社交獎勵隨意外傳。

### 可重覆任務的檔名

正式發布／存入 Community Scripts 的可重覆任務，檔名前綴統一使用：
- `OOTB_可重覆任務_<劇名>.md`

此命名與既有 `OOTB_初期任務_<劇名>.md` 的任務層級一致；**不得使用 `OOTB_可重覆劇本_<劇名>.md` 或 `OOTB_可重覆小型副本_<劇名>.md` 作正式檔名**。

「可重覆任務」是正式運行類別名稱；任務是否屬小型，另由規格頭 `劇本規模：小型` 約束，不把「小型」寫入類別名稱。

## Phase B：檢查

初稿完成後，**把設計過程視為不存在，只拿最終劇本 md**，先完整讀取並執行：
- [`檢查.md`](檢查.md)

所有正式劇本在一般檢查完成後，**必須再完整讀取並依序執行**：
- [`拿手檢查.md`](拿手檢查.md)
- [`社會名譽檢查.md`](社會名譽檢查.md)
- [`整備檢查.md`](整備檢查.md)

`拿手檢查.md` 是所有劇本共通的拿手與非戰鬥判定硬檢；即使劇本只引用了拿手規則、只使用少量非戰鬥判定，或自稱主要以戰鬥／追逐為主，也不能跳過。它會檢查正式拿手名稱、能力＋拿手搭配、熟練／專精是否能真正生效、裸能力是否吞掉適用拿手，以及 `文書／調查／追蹤／察覺／交涉／醫毒／格物` 等非正式 shorthand 是否被誤當角色卡拿手。

`社會名譽檢查.md` 是所有劇本共通的社會系統硬檢；它會檢查是否仍使用舊 `名望／聲譽／勢力關係／口碑` 數值、是否非法自創相對名譽對象、俠名／惡名／相對名譽倍率是否可直接結算，以及 NPC 是否真的因角色既有名譽改變主動透露、刻意隱瞞、准入、優勢／劣勢、修正值或下一步。

`整備檢查.md` 是所有劇本共通的出發前整備硬檢；它會檢查整備類型與安全空檔是否可直接執行、連續／突發因果是否成立、玩家是否獲得足夠但不劇透的補給資訊、食水／攜帶是否閉環，以及整備時間是否真的推進期限與世界。

若最終劇本宣告與任何已完成劇本存在前傳、後傳、平行、承接、共享事件、揭曉或其他明確跨劇本關連，則在四層共同檢查完成後，再完整讀取並執行：
- [`跨劇本關連檢查.md`](跨劇本關連檢查.md)

`跨劇本關連檢查.md` 會加驗關連樹目錄建立時點、穩定歸檔根、跨樹只連邊不合樹、component 發現完整性、客觀事實／branch state 一致性、多項直接關連宣告、跨劇本 NPC 身份，以及無前作紀錄基線。

若最終劇本明列：
- `運行類別：可重覆任務`

則在四層共同檢查全部完成後，再完整讀取並執行：
- [`可重覆任務檢查.md`](可重覆任務檢查.md)

若最終劇本本身不是可重覆任務，但最終 md 宣告與一份可重覆任務有前置、後傳、承接、平行或其他跨劇本關連，則在共同檢查後，至少執行：
- [`可重覆任務檢查.md`](可重覆任務檢查.md) **第 9 節「跨劇本前置隔離硬檢」**。

若最終劇本含必要文字／讀音機關，再完整讀取並執行：
- [`文字機關檢查.md`](文字機關檢查.md)

若最終劇本把任何正式門派的 `〈門派〉引薦` 列為可取得獎勵，再完整讀取並執行：
- [`入門引薦檢查.md`](入門引薦檢查.md)

單純因引薦而觸發本專項時，**不要**把該劇本誤判為門派專用任務，也不要套用門派專用任務 `R × m` 門派功績公式；其社會名譽仍按一般劇本 `E × r_T` 結算。

若最終劇本包含門派專用任務、`[來自〈門派〉]` 武學來源／解鎖、門派武學外流，或現役門人向外人教授本門武學，再完整讀取並執行：
- [`門派武學檢查.md`](門派武學檢查.md)

所有劇本的共同檢查順序固定為：
1. `檢查.md`
2. `拿手檢查.md`
3. `社會名譽檢查.md`
4. `整備檢查.md`

四層共同檢查完成後，再依最終 md 實際觸發的專項模組執行 `跨劇本關連檢查.md`、`可重覆任務檢查.md`、`文字機關檢查.md`、`入門引薦檢查.md`、`門派武學檢查.md`；同時觸發時全部都要通過。專項檢查彼此不互相豁免。

其中 `可重覆任務檢查.md` 的姓名實例化項，對最終 md 已依 `文字機關設計.md` 明確證明為必要、且通過 `文字機關檢查.md` 的**最小固定欄位**不作失敗判定；其他 NPC／其他姓名欄仍按全可變要求驗收。

檢查階段負責：完成品／大綱判定、格式硬檢、世界知識庫固定正典一致性、反交付／反大綱閘門、拿手與非戰鬥判定硬檢、社會名譽硬檢、出發前整備硬檢、偏離覆檢及發布前驗收；跨劇本關連另加驗根目錄建立時點、穩定歸檔、跨樹指向、component 自洽、多關連宣告及 branch state；可重覆任務另加驗事件可重現性、NPC／LOC／PROP／CLUE 實例化、實例識別、真相分支鎖定、重複獎勵上限及跨劇本前置隔離；文字機關另加驗世界內成因、字形／讀音實際可用性、普通話／粵語可達性及姓名最小固定合理性；入門引薦另加驗類別不得寫成門派專用任務、引薦只是可選獎勵之一、發薦權限、個人不可轉讓、替代獎勵及不得偷渡門派身份／武學／功績；門派武學另加驗來源標籤、解鎖上限、外流因果、NPC 教學與可直接寫回的武學來源資料。

只要 `檢查.md`、`拿手檢查.md`、`社會名譽檢查.md` 或 `整備檢查.md` 任一硬性項目不通過，就必須回到劇本正文補完，再重新檢查；不得以「GM 到時自行補」「作者心裡知道」「理論上可有其他線索」「GM 會知道 shorthand 對應哪項拿手」「GM 自己按名聲調整」「GM 自己給合理整備時間」視為通過。

若觸發跨劇本關連專項規格，`跨劇本關連檢查.md` 任一硬性項目不通過亦不得交付；不能把關連樹歸檔、跨樹指向、component 客觀事實、branch state 或漏列的直接關連留給 GM／後續作者自行猜測。

若屬「可重覆任務」，`可重覆任務檢查.md` 任一硬性項目不通過亦不得交付為該類別；只能回正文修正後重檢，或移除該類別並按一般 `once_per_character` 劇本處理。

若一般劇本與可重覆任務有跨劇本關連，而第 9 節前置隔離不通過，該關連關係亦不得交付；必須移除必要前置／handoff，或把來源事件改造成適合承接的非 repeatable 劇本。

若含必要文字／讀音機關，`文字機關檢查.md` 任一硬性項目不通過亦不得交付；不能把語音差異、粵語版本或姓名固定理由留給 GM 臨場補。

若觸發入門引薦專項規格，`入門引薦檢查.md` 任一硬性項目不通過亦不得交付；不能把引薦來源權限、替代獎勵、個人歸屬、重複取得或入門後果留給 GM 臨場補。

若觸發門派武學專項規格，`門派武學檢查.md` 任一硬性項目不通過亦不得交付；不能把來源標籤、武學解鎖上限、門派外流原因或 NPC 教學合理性留給 GM 臨場補。
