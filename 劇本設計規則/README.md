# 劇本設計規則

本目錄規範如何製作一份可直接交給 GM 運行的《武與俠》TRPG 劇本，並把「創作」與「驗收」分成兩個工作階段。

## Phase A：設計

先完整讀取：
- [`設計.md`](設計.md)

若打算把劇本設計成、或最終規格頭明列：
- `運行類別：可重覆小型副本`

則必須再完整讀取：
- [`可重覆小型副本設計.md`](可重覆小型副本設計.md)

再按需要查閱：
- `遊玩規則/`
- `內容庫/`
- 若需要理解 GM 如何在實際遊戲中處理某種資料，再讀 `GM規則/README.md` 及其指定子文件；可重覆小型副本另須遵守 `GM規則/可重覆小型副本.md`。

設計階段負責：交付形式、規格頭、世界真相、時間線、NPC、跨劇本關係、線索、場景、遭遇、危機、獎勵、歷練、終局、偏離處理及可直接運行的細節。

`可重覆小型副本設計.md` 是該運行類別的**加嚴補充規格**；只在該類別內適用。一般劇本不因規模小、NPC 名稱可變或情節簡單而自動取得重跑資格。

### 可重覆小型副本的檔名

正式發布／存入 Community Scripts 的可重覆小型副本，預設檔名前綴統一使用：
- `OOTB_可重覆任務_<劇名>.md`

此處使用「任務」與既有 `OOTB_入門任務_<劇名>.md` 的小型獨立任務命名層級一致；**不得使用 `OOTB_可重覆劇本_<劇名>.md` 作此類別的正式檔名**。`可重覆小型副本` 仍是規格頭中的運行類別名稱，不因檔名使用「任務」而改名。

## Phase B：檢查

初稿完成後，**把設計過程視為不存在，只拿最終劇本 md**，再完整讀取：
- [`檢查.md`](檢查.md)

若最終劇本明列：
- `運行類別：可重覆小型副本`

則在一般檢查全部完成後，再完整讀取並執行：
- [`可重覆小型副本檢查.md`](可重覆小型副本檢查.md)

檢查階段負責：完成品／大綱判定、格式硬檢、反交付／反大綱閘門、偏離覆檢及發布前驗收；可重覆小型副本另加驗事件可重現性、全 NPC 換名、實例識別、真相分支鎖定及重複獎勵上限。

只要 `檢查.md` 任一硬性項目不通過，就必須回到劇本正文補完，再重新檢查；不得以「GM 到時自行補」「作者心裡知道」「理論上可有其他線索」視為通過。

若屬「可重覆小型副本」，`可重覆小型副本檢查.md` 任一硬性項目不通過亦不得交付為該類別；只能回正文修正後重檢，或移除該類別並按一般 `once_per_character` 劇本處理。

## 權威邊界

- **遊戲機制是甚麼**：`遊玩規則/`
- **可引用內容是甚麼**：`內容庫/`
- **GM 如何運行**：`GM規則/`
- **一般劇本如何設計**：本目錄 `設計.md`
- **可重覆小型副本如何設計**：本目錄 `可重覆小型副本設計.md`（只在該類別加嚴適用）
- **一般劇本是否合格可交付**：本目錄 `檢查.md`
- **可重覆小型副本是否合格可交付**：先通過 `檢查.md`，再通過 `可重覆小型副本檢查.md`

同一規則不應在多個模組各自建立不同版本。若 `設計.md` 或類別補充規格要求某資料供 GM 使用，GM 的實際運行行為仍以 `GM規則/` 的權威主持流程為準。
