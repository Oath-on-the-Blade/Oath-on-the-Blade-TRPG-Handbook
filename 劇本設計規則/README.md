# 劇本設計規則

本目錄規範如何製作一份可直接交給 GM 運行的《武與俠》TRPG 劇本，並把「創作」與「驗收」分成兩個工作階段。

## Phase A：設計

先完整讀取：
- [`設計.md`](設計.md)

再按需要查閱：
- `遊玩規則/`
- `內容庫/`
- 若需要理解 GM 如何在實際遊戲中處理某種資料，再讀 `GM規則/README.md` 及其指定子文件。

設計階段負責：交付形式、規格頭、世界真相、時間線、NPC、跨劇本關係、線索、場景、遭遇、危機、獎勵、歷練、終局、偏離處理及可直接運行的細節。

## Phase B：檢查

初稿完成後，**把設計過程視為不存在，只拿最終劇本 md**，再完整讀取：
- [`檢查.md`](檢查.md)

檢查階段負責：完成品／大綱判定、格式硬檢、反交付／反大綱閘門、偏離覆檢及發布前驗收。

只要 `檢查.md` 任一硬性項目不通過，就必須回到劇本正文補完，再重新檢查；不得以「GM 到時自行補」「作者心裡知道」「理論上可有其他線索」視為通過。

## 權威邊界

- **遊戲機制是甚麼**：`遊玩規則/`
- **可引用內容是甚麼**：`內容庫/`
- **GM 如何運行**：`GM規則/`
- **劇本如何設計**：本目錄 `設計.md`
- **劇本是否合格可交付**：本目錄 `檢查.md`

同一規則不應在多個模組各自建立不同版本。若 `設計.md` 要求某資料供 GM 使用，GM 的實際運行行為仍以 `GM規則/` 的權威主持流程為準。
