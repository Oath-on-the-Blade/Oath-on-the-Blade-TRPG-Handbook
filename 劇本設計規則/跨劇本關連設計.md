# 跨劇本關連設計

本模組是一般劇本在前傳、後傳、平行、承接、分支、匯流、共享事件、揭曉或其他明確跨篇關連時的專項補充規格。

目前一般關連只在**同一棵關連樹內**建立；不建立跨樹劇本專用關連。單一 `A → B` 完全合法，但鼓勵在背景與 state 自然支持時建立多分支、多來源與匯流。

---

## 1. 何時觸發

只要新劇本實際依賴另一份既有劇本的任一劇本專用資料，就視為有直接關連，包括：

- 既有 `ending_id`／持久 state；
- 既有劇本 NPC 身份或狀態；
- 既有劇本專用物件、證物、制度後果或地方真相；
- 前作事件的公開結果、責任、物權、傷亡或其他持續後果；
- 明確前傳／後傳／平行／承接／分支／匯流。

只因同地區、同門派、同年代、同主題或同一 Handbook 共用正典，**不構成**劇本關連。

若本篇實際同時依賴兩個或以上既有樹內任務的專用資料，所有實際來源都必須列為直接來源，不得只掛一個方便的 anchor。

### 1.1 關連是任務間關係層，不是互斥任務類型

「有跨劇本關連」只回答：**本篇與哪些既有任務之間存在可驗證的 state／因果／身份／物件承接。** 它不是一個會把其他定位排除掉的任務類型。

因此，只要各自的專項規則與世界因果成立，同一個關連樹節點可以同時具有例如：

- 一般冒險或特殊獎勵冒險；
- 高難度結構；
- 門派專用任務；
- 門派武學正式授權／武學特殊獎勵；
- 門派入門引薦相關獎勵或委託；
- 其他由 Handbook 正式定義、且不與其自身運行類別衝突的定位。

硬性原則：

1. **不得因劇本成為關連任務，就自動把它降格成普通一般任務、取消門派引薦／武學、降低難度或禁止特殊獎勵。** 是否採用這些定位，只看本篇內容是否自然成立。
2. **關連樹節點不要求同等級或同難度。** 前後篇可以有不同建議等級、歷練基準 R、規模、戰鬥強度、資源壓力或整體難度；可以自然升階，也可以因事件規模縮小而降階。
3. 不得為了「看起來像同一系列」硬把後作調成與前作相同 R／相同敵人數值／相同危機強度。每篇仍由自己的世界規模、武學獎勵節點、時間資源與實際威脅決定。
4. 若本篇同時觸發門派武學、入門引薦、文字機關或其他專項，**全部專項同時適用**；跨劇本關連不提供豁免。
5. 若作者檢查後決定本篇不提供門派引薦／武學、也不採高難度，這可以完全合法，但理由必須是本篇沒有足夠授權、傳承、危機結構或劇情需要，而不是「關連任務不能有這些內容」。
6. **戰役與可重覆任務仍是例外邊界。** 戰役階段依戰役總劇本／campaign state 流程；可重覆任務依其 `independent`、新 `game_id` 實例化與跨劇本前置隔離規則。關連層不得用來繞過這些專項限制。

## 2. 關連樹與「關連樹目錄」

### 2.1 關連樹目錄是 Markdown 關係索引文檔，不是資料夾

當一個原本獨立的根任務第一次產生關連任務時，建立：

`OOTB_任務_<根任務名>_關連樹目錄.md`

這個檔案是作者／維護者使用的**關係索引文檔**，用途是集中說明整棵樹的節點、直接關連、branch/state 路由與背景一致性。

硬性規則：

1. **不得因建立關連樹而搬動根任務或任何劇本檔。**
2. **不得建立同名資料夾代替此 `.md` 文檔。**
3. 根任務及所有關連任務維持各自原有 repo 路徑與檔名。
4. 第一份關連任務建立時，同一變更必須建立／初始化這份目錄文檔，至少列入根任務、第一份關連任務及其直接邊。
5. 之後每次新增、刪除或改變樹內直接關連、`ending_id`／持久 state 路由或背景基線，都要同步更新同一份目錄文檔。
6. 目錄文檔本身不是可玩劇本，不需要一般劇本 Phase B；它是關連一致性的 repo 索引與維護資料。
7. 目錄文檔不能覆寫個別劇本正文。若索引與劇本正文衝突，先修正不一致，不能以索引偷偷改寫劇本真相。

### 2.2 穩定根

「根任務」是這棵關連樹首次建立時作為原始延伸 anchor 的既有任務。目錄檔名建立後保持穩定：

- 日後可以加入時間上更早的前傳；
- 可以從中間節點長出新分支；
- 可以出現多來源匯流；
- 但不因此重新命名根目錄文檔。

這個「根」是**穩定索引根**，不保證是故事時間線最早事件。

### 2.3 一份任務只屬一棵一般關連樹

每份一般關連任務只能列在一份 `OOTB_任務_<根任務名>_關連樹目錄.md` 中。現階段不建立跨樹直接關連，也不把兩棵樹合併成一棵大樹。

若設計真的需要另一棵樹的劇本專用 `ending_id`、NPC state、物件去向或局部真相，應重新設計使來源落在同一棵樹，或另按未來規則處理；不能私下跨樹讀取。

---

## 3. 關連樹目錄文檔最低內容

目錄文檔至少要包含：

1. **根任務與根 `script_id`**；
2. **樹內節點表**：劇名、檔名／`script_id`、直接來源、關連類型、是否必要前置；
3. **關連圖**：能看出直接邊與分支／匯流；
4. **共同背景基線**：整棵樹不得無聲改寫的客觀事實；
5. **branch-specific state**：只在某些 ending／路線成立的狀態；
6. **可累積 state**：可同時成立、可被後作共同讀取的狀態；
7. **互斥 state**：不能在同一 campaign 同時成立的狀態；
8. **主要 ending／state → 後續映射**：至少列出會影響可達性的條件；
9. **多來源條件**：若新篇有兩個以上直接來源，明列 `AND`／`OR`／互斥／其他可執行邏輯；
10. **必要維護註記**：例如某前作 NPC 是可替代來源、某物權必須按 receipt 帶入、某武學來源不可由傳聞補成正式來源。

索引應以**保守、不創造新正史**為原則。若某個關係只在劇本正文寫成「可能承接」而沒有固定 branch，目錄也只能寫到同等確定度。

## 4. 樹內分支：ending 與 state 是 many-to-many

一般關連樹不是只能一條直線。

合法例子：

```text
A → B
A ∥ C
A → D ← B
```

也合法：

```text
A:ending-1 → B
A:ending-1 → C
A:ending-2 → D
```

### 4.1 一個 ending 可以開啟多個後續

`A:ending-1 → B + C` 完全合法。

B、C **不會因為同由 `ending-1` 開啟便自動互斥**。玩家能否先後跑 B、C，要看兩份後作實際產生的持久 state 是否衝突。

### 4.2 一個後續可以接受多個前作狀態

例如：

- `A:ending-1 OR A:ending-2 → C`
- `A:ending-1 AND B:state-x → D`
- `A:ending-3` 與 `B:state-y` 互斥，故 D 不可達。

最終劇本必須把這些條件寫到 GM 可執行，而不是只寫「視前作結果調整」。

### 4.3 分支不是背景裂成多個互不相干世界

同一棵樹仍共享一個背景基線。不同 branch 可以有不同人物狀態、物權、責任、公開程度或制度後果，但不能把已確立的共同客觀事實任意改寫。

---

## 5. 鼓勵樹內多來源與匯流

選題時應主動檢查：新篇是否自然承接了兩個或以上既有樹內節點。

例如：

```text
A → B
A → C
B + C → D
```

若 D 的核心前提同時依賴 B 的制度後果與 C 的人物／物件 state，B、C 都是 D 的直接來源。

但「鼓勵」不是配額：

- 不要為增加邊數硬拉無關任務；
- 不要把只共享地區／門派的節點冒充直接來源；
- 不要把不相容 branch 強行拼成同一背景；
- 單一自然延伸仍然合格。

---

## 6. 寫新關連任務前，先掃整棵樹

作者至少要讀：

1. `OOTB_任務_<根任務名>_關連樹目錄.md`；
2. 本篇所有直接來源全文；
3. 目錄指出、且會影響本篇共同背景／branch state 的其他必要樹內劇本；
4. 涉及 `NPC#前作編號@前作劇名` 時，原人物所在劇本與已知後續狀態。

然後建立作者用 ledger，至少區分：

- 全樹共同客觀事實；
- 各 ending／branch-specific state；
- 可累積 state；
- 互斥 state；
- 已死亡／失蹤／離職／敵對／被捕的 NPC 狀態；
- 物件與證物的所有權、保管、毀損、交官、遺失；
- 本篇準備新增的直接邊。

不能只讀最近一篇便假定更早節點不再有效。

---

## 7. 背景一致性硬規則

### 7.1 已確立客觀事實不得無聲 retcon

若樹內既有劇本已確立某客觀事實，新篇不得在沒有可執行解釋下改成相反事實。

若真的需要新增揭曉，只能是：

- 早前角色／NPC 未知的更深層事實；或
- 能與既有觀察同時成立的新資訊。

不能把已被直接驗證的事實簡單宣告為「其實不是」。

### 7.2 branch 結果仍是 branch

一個 ending 造成的死亡、被捕、物權、制度改革、公開責任或聲譽，不得自動升格為整棵樹共同歷史。

### 7.3 `independent` 關連劇本要有無前作基線

若後作標示 `連續性：independent`，且前作不是必要前置：

- 必須提供沒有前作紀錄時的完整基線；
- 有存檔時，只按實際 `ending_id`／持久 state 疊加 overlay；
- 不能因沒有前作紀錄便偷偷指定某個前作 ending 已發生。

若前作是正文明列的必要前置，則可不提供無前作基線，但必須清楚寫明可接受的來源 ending/state。

---

## 8. 跨劇本 NPC

既有 NPC 再出場時仍使用：

`NPC#前作編號@前作劇名`

硬性要求：

- 不另分配一個本篇 NPC 編號假裝是新人；
- 保留既有姓名／身份映射；
- 讀取已保存的死亡、失蹤、離職、敵對、被捕等狀態；
- 若該 NPC 不是必要唯一資訊源，應提供替代來源；
- 若其出場是硬前置，必須在 branch/state 條件中明示。

---

## 9. 與可重覆任務的關係

若來源是可重覆任務，仍受 `可重覆任務設計.md` 的跨劇本前置隔離限制。關連樹與目錄文檔不會令 repeatable instance 自動變成可永久承接的單次正史節點。

本節也是 1.1 的邊界：即使某可重覆任務同時涉及門派引薦、門派武學或其他特殊獎勵，也不能因「它也是關連題材」便把某一個 `game_id`、`ending_id`、NPC、LOC／PROP／CLUE 或本輪真相升格成一般關連樹的必要固定前置。

---

## 10. 作者工作流

1. 判斷是否觸發跨劇本關連。
2. 找到來源所屬關連樹；若來源尚未有任何關連，這次就是第一次建立樹。
3. 第一次建立樹時，新建 `OOTB_任務_<根任務名>_關連樹目錄.md`；**不搬檔、不建資料夾**。
4. 讀目錄與所有會影響本篇的樹內來源，整理共同背景／branch state ledger。
5. 先獨立判斷本篇本身是否自然屬高難度、特殊獎勵、門派專用、門派武學、門派引薦或其他專項；**不要因它是關連任務便預先排除。**
6. 主動檢查是否有自然的多來源關連，但不強求。
7. 寫本篇直接來源、`AND`／`OR`／互斥條件、無前作基線、NPC／物件承接與每個主要 ending 新增的持久 state。
8. 若本篇同時觸發其他專項，按各專項規則完成其授權、來源、難度、R、獎勵與運行資料；樹內前後篇不需同等級／同難度。
9. 更新關連樹目錄文檔，把新節點、直接邊、可達 state 與共同背景補入。
10. 完成劇本正文後，按一般 Phase B，再執行 `跨劇本關連檢查.md` 與所有實際觸發的其他專項檢查。

一句話：**劇本檔留在原位；關連樹目錄是一份持續更新的關係索引文檔。樹內可以分支、匯流、多來源，也可以自然跨越不同等級、難度與合法任務定位；共同背景與 branch state 仍必須自洽。**
