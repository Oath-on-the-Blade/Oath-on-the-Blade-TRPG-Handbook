# 跨劇本關連設計

本文件規範**一般劇本在同一棵關連樹內**的前傳、後傳、平行、承接、共享事件、揭曉、分支與匯流。其目的不是把關連樹改造成固定戰役，而是讓同一根任務延伸出的多篇劇本在背景、客觀事實、NPC 身份、時間線與持久 state 上保持自洽，同時鼓勵樹內形成真正的多節點關連，而不是長期只做單一 A → B 延伸。

正式戰役內部的總綱、篇章接口、campaign state 與戰役級 NPC 主鍵仍以 `戰役總劇本設計.md`、`戰役劇本師規則.md` 為權威。

**目前一般關連樹不建立跨樹關連。** 不同 `_任務_<根任務名>_關連樹目錄/` 之間不得以另一棵樹的劇本專用真相、`ending_id`、NPC state、物件去向或其他局部 state 建立直接關連邊。不同樹仍可共同引用 Handbook 的世界知識庫、內容庫與其他共用正典；這不構成跨劇本關連。

---

## 1. 何時觸發

只要當前劇本宣告與同一關連樹內任何已完成劇本存在以下任一關係，就必須使用本模組：

- 前傳；
- 後傳；
- 平行關連；
- 承接／延伸；
- 由某個或某組 `ending_id`／持久 state 開啟的分支；
- 同時承接兩篇以上樹內任務的匯流；
- 共享同一事件、人物、物件或局部歷史，且該共享內容會影響兩篇以上劇本的真相、狀態或玩家理解；
- 後作揭曉、重解讀或補充前作已建立的局部事實；
- 其他正文明確宣告的樹內跨劇本關連。

單純同在同一道、同用某門派、同引用世界知識庫固定人物，**不自動構成跨劇本關連**。只有當本篇對同樹另一篇的劇本專用真相、既有事件結果、跨劇本 NPC、局部世界狀態或敘事因果有實際承接時，才建立關連邊。

---

## 2. 關連樹目錄與直接關連

### 2.1 第一個關連任務時才建立目錄

一份獨立任務尚未有任何關連任務時，**不預先建立空的關連樹目錄**。

當它第一次產生前傳、後傳、平行、承接、分支或其他直接關連任務時，才建立：

`_任務_<根任務名>_關連樹目錄/`

此處的**根任務**是「第一個關連任務建立時，被選作原始延伸基準的既有任務」。它是穩定歸檔根，不要求永遠是世界時間最早的一篇；日後即使加入更早的前傳，也不改名或換根。

建立目錄時：

1. 根任務與第一份關連任務一併歸入該目錄；
2. 之後所有直接承接這棵樹內任務的新關連任務，均存入同一目錄；
3. 若搬動既有根任務會令 repo 內相對路徑／明確連結失效，同一變更必須同步修正；
4. 目錄名一經建立即保持穩定，不因新增前傳、分支、匯流或枝幹而改根。

既有舊劇本若在本規則生效前已形成關連但仍散放於 repo 根目錄，不要求只為規則改版立即大規模搬檔；**下一次為該關連樹新增任務或進行結構性維護時**，應補建目錄並一次完成歸檔與連結修正。

### 2.2 一份任務只屬一棵關連樹

一份正式劇本只屬於一棵關連樹。不得為了建立關連，把同一劇本複製到兩個根目錄；也不得讓一份新劇本同時把兩棵既有關連樹的劇本專用 state 當成來源。

若構想需要同時依賴兩棵不同樹，應重新選題或把依賴降回 Handbook 共用世界背景；**不能以此建立跨樹關連。**

### 2.3 直接關連可以是一對一，也可以多來源

「直接關連」指本篇明確與同樹另一份劇本建立前傳／後傳／平行／承接／分支／共享事件等關係。

例如：

- A → B：B 是 A 的單一後續；
- A ∥ B：A 與 B 是平行關連；
- A → C ← B：C 同時承接同樹 A、B；
- A — B — C：C 沒有直接連 A，但三篇仍在同一關連樹內。

**單一延伸完全合法。** 但作者不得因模板習慣只選一個 anchor；若本篇實際同時依賴兩篇以上樹內任務建立的真相、人物、物件或 state，必須把全部直接來源列明。

## 3. 以結局與 state 長出分支

### 3.1 結局可以開啟不同分支

來源任務可以把不同 `ending_id`／持久 state 導向不同後續任務。例如：

- `ending-a` → 可開啟 B；
- `ending-b` → 可開啟 C；
- `ending-c` → 可開啟 D。

這些分支不是新的關連樹；全部仍留在同一 `_任務_<根任務名>_關連樹目錄/`。

### 3.2 一個結局可以開啟多於一個分支

**不要求一個結局只能對應一份後續任務。** 同一 `ending_id`／持久 state 可以同時使 B、C、D 等多份樹內任務成立。

例如：

- `ending-a` → B、C 都可開啟；
- 玩家完成 B 後，只要 B 沒有產生與 C 前置條件互斥的新 state，C 仍可繼續遊玩；
- 若 B 的結果確實令 C 的前置世界狀態失效，C 才因**明確 state 衝突**而關閉，而不是因「它們原本都是 ending-a 的分支」便自動互斥。

因此，「分支」描述的是**可達路徑**，不是自動的排他選單。

### 3.3 一份後續任務也可接受多組來源 state

同一後續任務可以接受一個或多個合法前置狀態，例如：

- `ending-a` 或 `ending-b` 都可進入 B，但開場細節不同；
- A 的 `ending-a` ＋ D 的某持久 state 同時存在時才開啟 C；
- A、B 兩篇同樹任務均已完成，且其 state 相容時，才開啟匯流任務 E。

這類多來源／多條件關連是**鼓勵的樹內結構**，但必須在本篇清楚列出前置邏輯：`AND`、`OR`、互斥條件及沒有相關紀錄時的處理。

### 3.4 不得拼接互不相容的 branch

多來源關連不能把同一桌不可能同時成立的背景硬拼起來。例如來源 A 的兩個互斥 `ending_id` 不能被新篇同時當成已發生；某 NPC 在 branch X 已死亡、branch Y 才生還，也不能在沒有合法 state 解釋下同時成立。

作者必須區分：

- **樹內共同背景／不變事實**：所有 branch 都成立；
- **branch-specific state**：只在某個或某組結局成立；
- **可累積 state**：不同任務結果可以同時存在；
- **互斥 state**：一旦其中一項成立，另一項不能同時成立。

## 4. 創作前先盤點整棵樹

### 4.1 掃描完整樹內 component

選定直接來源後，先讀 `_任務_<根任務名>_關連樹目錄/` 內所有任務的關連定位，再以劇名、`script_id`、`@前作劇名`、`ending_id`、持久 state 及反向引用確認整棵樹的既有關連。

作者不能只讀「我選中的那一篇前作」就開始寫新真相。

### 4.2 建立作者用關連帳

關連帳是創作工作資料，不要求作為額外交付檔。至少記錄：

- 劇本名稱與 `script_id`；
- 與其他樹內節點的直接關連類型；
- 世界內先後／平行時點；
- 已明確成立、不得無聲推翻的客觀事實；
- 所有 branch 共通的背景基線；
- 仍刻意未知、只屬傳聞或尚未定案的事項；
- 各主要 `ending_id` 及其持久 state；
- 哪些 state 可累積、哪些互斥；
- 每個結局／state 可開啟哪些後續任務；
- 每份後續任務需要哪些 `AND`／`OR` 前置；
- 跨劇本 NPC 的穩定識別鍵／既有 alias；
- 會被多篇共同使用的地點、文書、物件與勢力狀態。

### 4.3 閱讀深度

以下劇本必須完整讀取：

1. 本篇所有直接關連來源；
2. 同樹中任何其真相、`ending_id`、NPC 身份、物件去向、地點狀態或時間線會實際影響本篇的節點；
3. 任何作者無法只靠關連定位／結局段確認是否與本篇衝突的節點。

其餘同樹節點至少核對關連定位、GM 真相、主要結局與會延續的世界狀態；有疑義即升級為完整讀取。

## 5. 樹內背景一致性是硬規格

### 5.1 客觀事實不得無聲改寫

同樹已由既有劇本 GM 真相明確建立的客觀事件、責任、身份、死亡、生還、物件來源、地點結構或局部歷史，本篇不得因需要新反轉而直接改成相反答案。

後作可以補充空白、揭示人物當時不知道的更深資訊、重解讀既有線索，或證明角色／NPC 的推論有誤；但必須保留已明確成立的客觀事實。真正需要 retcon 時，先修來源劇本／共同規則並處理版本相容性。

### 5.2 共享背景與 branch 差異必須分開

同一棵樹可以有彼此不同的 branch，但所有 branch 必須共享能共同成立的背景基線。例如地理、事件先後、某宗舊案確實發生、某物件來源、某 NPC 的基礎身份等，不得因選不同 branch 就任意改寫。

只應由 `ending_id`／持久 state 決定的事項，例如 NPC 是否死亡、證物歸誰、某機構是否被查封、某債是否已清、某人是否與玩家決裂，必須保持為 branch-specific state。

### 5.3 玩家履歷只讀實際成立的 state

關連樹是作者一致性範圍，不代表玩家必然跑過所有節點。GM 只讀入角色履歷／該桌 save 真正存在的前作 `ending_id` 與持久 state。

若本篇是 `independent`，沒有任何前作紀錄時仍須有完整可運行基線；若本篇明確是合法 `continuous` 後續，則把必要前置、允許 state、開場時點與帶入狀態寫清楚。

### 5.4 跨劇本 NPC 必須沿用身份

跨劇本 NPC 的基本識別依 `設計/交付規格與引用.md` 的 `NPC#前作編號@前作劇名`。若同樹較早節點已建立 provenance alias／遷移對照，本篇必須沿用；若人物狀態因不同 branch 分歧，本篇按實際 state 處理姓名、傷勢、立場、死亡／生還與所知資訊。

## 6. 鼓勵樹內多節點關連

本規則不要求每篇都至少有兩個直接來源，但**選題時應優先檢查能否自然利用樹內已有兩個以上節點**，而不是習慣性永遠再長一片只連單一 anchor 的新葉。

適合的樹內多節點關連包括：

- A 的某個結局開啟 B、C 兩條可並行分支；
- D 同時承接 A 留下的制度後果與 B 建立的人物關係；
- E 只有在 A 與 C 的兩項相容 state 都成立時才開啟；
- F 可由 A 或 B 任一路徑進入，但依來源 state 有不同開場；
- 兩條同樹枝幹在後作匯流，重新處理它們共同留下的問題；
- 某 NPC 在兩個樹內任務分別建立不同關係，新篇同時利用兩邊已成立的資料。

不應為了「多關連」硬造無因果價值的 crossover。只有同地區、同門派、同年代但沒有劇本專用承接，不需要建立直接關連邊。

---

## 7. 最終劇本的關連表示

任何觸發本模組的最終劇本，規格頭或開頭關連欄位至少列出：

- **關連樹**：`_任務_<根任務名>_關連樹目錄/`；
- **直接關連來源**：同樹一篇或多篇；
- 每一篇的**關連類型**：前傳／後傳／平行／承接／分支／匯流／共享事件／其他；
- 是否為必要前置；
- 會讀取哪些 `ending_id`／持久 state；
- 多來源時的條件邏輯：`AND`／`OR`／互斥；
- 本篇 `independent`／`continuous` 的處理方式。

正文另設「關連定位」或等價段落，至少說清：

1. 本篇在世界時間與因果上位於各直接來源的甚麼位置；
2. 哪些是整棵樹共同背景；
3. 哪些差異只由指定 `ending_id`／持久 state 觸發；
4. 每項 state 只改變甚麼；
5. 哪些來源 state 可同時成立、哪些互斥；
6. 本篇完成後新增哪些持久 state，以及它們可能開啟／關閉哪些樹內後續；
7. `independent` 劇本沒有前作紀錄時如何完整開場；若是合法必要前置的 `continuous`，則明列缺少前置時不能開局的原因。

不要求把整棵樹的所有節點抄進最終劇本；完整盤點是作者的一致性工作。

---

## 8. 與可重覆任務的關係

若任何直接來源是可重覆任務，除本文件外，仍須遵守 `可重覆任務設計.md` 4.1「跨劇本前置隔離」。

可重覆任務不能成為另一劇本的必要前置基礎；後作不能依賴某一次 repeatable run 才成立的唯一人物、唯一真相或唯一 handoff。某次 run 結果可作可選 state overlay，但必須有無該 run 的完整基線。

---

## 9. 作者流程

凡創作關連劇本：

1. 選定一棵既有關連樹；若這是根任務的第一份關連任務，才建立 `_任務_<根任務名>_關連樹目錄/` 並完成歸檔；
2. 掃描整棵樹的直接關連、`ending_id`、持久 state、NPC、物件與既有背景；
3. 建立作者用關連帳，區分共同背景、branch-specific state、可累積 state 與互斥 state；
4. 選定一篇或多篇**同樹**直接來源；優先考慮是否能自然利用多於一個樹內任務；
5. 寫清本篇前置邏輯及可達路徑；一個 ending 可開多個分支，一個後續也可接受多組來源 state；
6. 再寫本篇新真相與時間線，確認沒有無聲 retcon 或拼接互斥 branch；
7. 為 `independent` 劇本寫無前作紀錄基線；按實際 `ending_id`／state 寫覆蓋；
8. 寫明本篇結局新增的持久 state，以及它們對後續樹內任務的開啟／關閉效果；
9. 完成初稿後，除一般 Phase B 外，另執行 `跨劇本關連檢查.md`。

一句話：

**先在一棵樹內把背景做成一致的；讓不同結局自然長出可並行、可匯流、可多來源的分支；暫不建立跨樹關連。**
