# 劇本設計規則：門派入門引薦獎勵檢查

本文件只檢查**最終劇本 md**。只要劇本把任何正式門派的：

`〈門派〉引薦｜可宣告使用以申請入門｜未使用`

列為角色可取得獎勵，就必須在一般 `檢查.md → 拿手檢查.md → 社會名譽檢查.md → 整備檢查.md` 全部通過後，再執行本文件。

**有引薦不等於可重覆任務，也不等於任何新的任務類型。** 只有當最終 md 本身原已明列 `運行類別：可重覆任務`／`replay_policy: repeatable` 時，才另外完整執行 `可重覆任務檢查.md`。

任一硬性項目失敗，該引薦獎勵不得交付為完成狀態。

---

## 1. 任務類型保持不變硬檢

逐項確認：

- [ ] 最終 md 沒有只因加入引薦獎勵，便把一般任務改成「入門引薦委託」或其他新運行類別。
- [ ] 沒有只因加入引薦，把 `once_per_character` 改成 `repeatable`。
- [ ] 沒有只因加入引薦，把 `independent`／`continuous`、劇本規模、建議等級、R、難度或冒險分類強制改成固定模板。
- [ ] 檔名前綴仍依原本任務／運行類別使用；沒有要求一般任務改用專用引薦前綴。
- [ ] 若本篇是關連任務，關連來源、關連樹與原本定位仍保留；沒有因引薦而退出／更換關連樹。
- [ ] 若本篇本身另是可重覆任務、戰役階段、門派專用任務、門派武學任務或其他專項，該專項仍按原規則完整適用。

**失敗條件**：把「引薦獎勵」誤當成會覆寫底層任務類型的分類。

---

## 2. 引薦是否真的適合本篇硬檢

最終 md 必須能直接回答：

- [ ] 角色做了甚麼，足以令目標門派願意替其入門申請背書？
- [ ] 這項行動為何與該門派的收徒標準、理念、能力需求、責任或關係有關？
- [ ] 誰知道角色做了這件事？
- [ ] 哪個結局／哪些 state 才能取得引薦？
- [ ] 個人參與條件是否足以排除只在終局掛名領獎的人？

若唯一理由只是「幫過門派」「普通門人很喜歡角色」「劇情剛好在山門附近」，即不通過。

---

## 3. 角色資格與替代獎勵硬檢

逐項確認：

- [ ] 尚未加入目標門派、且沒有同派有效引薦的合資格角色可以取得引薦。
- [ ] 已是目標門派正式成員者不能再取得本派引薦。
- [ ] 已持有同一門派有效未使用引薦者不能取得第二份。
- [ ] 引薦是個人獎勵時，至少另有一項已預寫的個人替代獎勵。
- [ ] 已是門人、已有有效引薦或單純不想取引薦者，仍可正常取得該替代獎勵。
- [ ] 替代獎勵有具體內容、交付者與交付狀態；不是「GM 另給合理補償」。
- [ ] 沒有把引薦換算成固定銀兩買價。
- [ ] 不同角色可各自選擇；若世界內確有名額上限，名額原因已在開局前成立，且未取得者仍有完整替代獎勵。

任一不通過即失敗。

---

## 4. 發薦來源與權限硬檢

逐項確認：

- [ ] 目標門派是 Handbook 正式存在的具名門派。
- [ ] 最終 md 有具體人物或制度負責發出／批准引薦。
- [ ] 該人物／制度真的有合理權限，不是普通門人因一時欣賞便自行代表全派。
- [ ] 若遞交者不是批准者，正文清楚分開遞交與批准權。
- [ ] 使用最低足夠組織層級，沒有為普通事件硬拉掌門／首領親自出場。
- [ ] 本次角色的實際行動與發薦理由可直接連起來。

若本篇不是可重覆任務：

- [ ] 可依世界知識正常使用本篇具名 NPC、固定世界人物或門派制度；沒有套用不屬於本篇的「固定人物一律禁止」限制。

若本篇本身是可重覆任務：

- [ ] 發薦 NPC、地點、事件與其他實例資料仍完整符合 `可重覆任務檢查.md`；沒有因引薦而豁免新 `game_id` 實例化或固定人物限制。

任一不通過即失敗。

---

## 5. 角色卡寫回與個人歸屬硬檢

引薦成立時，GM 必須可直接寫回：

`〈門派〉引薦｜可宣告使用以申請入門｜未使用`

並且最終 md 清楚說明：

- [ ] 引薦屬於哪名角色本人。
- [ ] 不可轉讓、出售、贈送或作隊伍共有。
- [ ] 同一角色同一門派同時最多一份有效引薦。
- [ ] 一份引薦只支援一次正式入門申請。
- [ ] 引薦本身不保證入門成功。

任一不通過即失敗。

---

## 6. 取得次數與 `replay_policy` 硬檢

共同檢查：

- [ ] 已是門人者不能取得同派新引薦。
- [ ] 正持有有效引薦者不能取得第二份。
- [ ] 引薦不可轉讓、出售、共享或疊加成額外入門修正。

### 6.1 原劇本為 `once_per_character`

若本篇是 `once_per_character`：

- [ ] 沒有因入門判定失敗而允許角色重跑同一劇本刷第二份引薦。
- [ ] 正文沒有把「引薦可重新取得」偷寫成對同一 `script_id` 的重跑權。
- [ ] 角色日後若要再申請，只能由另一份合法劇本／正式來源重新取得新引薦。

### 6.2 原劇本為 `repeatable`

若本篇本身是可重覆任務：

- [ ] 已另完整通過 `可重覆任務檢查.md`。
- [ ] 同一 `game_id` 不得重領、補領第二份或藉不同 `variant_id` 重複取得。
- [ ] 已使用且失敗／失效後，只能在新的 `game_id` 再次完整參與並符合發薦條件時重新取得。
- [ ] 歷練、銀兩、正向名譽及其他永久獎勵的重覆上限仍由該可重覆劇本正文完整處理。

**失敗條件**：因為引薦本身可在世界中再次取得，就錯把所有含引薦劇本都視為 repeatable。

---

## 7. 關連任務引薦硬檢

若本篇是跨劇本關連節點：

- [ ] 引薦由本篇自己的事件、人物／制度與結局建立，不是只因「前作幫過該門派」便自動發出。
- [ ] 所有會影響引薦資格的前作 `ending_id`／state 都已按 `跨劇本關連設計.md` 明列可執行效果。
- [ ] 前作不是必要前置時，沒有前作紀錄仍有完整基線；沒有偷指定某個前作好結局為正史。
- [ ] 引薦只寫入取得角色自己的持久狀態，不偷升格成整棵關連樹共同 state。
- [ ] 關連樹目錄若提及引薦，只記錄「哪些角色在何條件可取得」的索引資訊，不讓其他角色／其他節點自動繼承。
- [ ] 沒有因引薦而要求樹內節點同等級、同 R、同難度或同獎勵結構。

任一不通過即失敗。

---

## 8. 不得偷渡入門、武學、配給或名譽

單純取得引薦時，確認**沒有**同時自動：

- [ ] 成為門派成員；
- [ ] 通過入門判定；
- [ ] 取得門派免費整備配給；
- [ ] 取得任何 `[來自〈門派〉]` 武學來源；
- [ ] 提高任何武學解鎖上限；
- [ ] 取得內門／真傳／職位；
- [ ] 因「得到引薦」本身直接增加門派相對名譽。

若劇本另外真正授予門派武學，必須再完整通過 `門派武學檢查.md`；不能把引薦當作武學來源證明。

任一偷渡即失敗。

---

## 9. 社會名譽沿用原任務類型硬檢

引薦不改變原劇本的社會名譽公式。

逐項確認：

- [ ] 一般任務／一般關連任務仍按一般劇本 `E × r_T` 結算。
- [ ] 若本篇本身另是門派專用任務，仍使用門派專用任務原本適用的公式與門派功績規格，而不是因引薦改成一般公式。
- [ ] 若本篇本身是可重覆任務，正向名譽重覆上限仍按該劇本正文。
- [ ] 取得引薦本身不是加相對名譽的原因。
- [ ] 所有非零名譽變化仍有事件、傳播與可靠歸因支持。

**失敗條件**：只因加入引薦，就把原本的一般／關連任務改套 `R × m`，或反過來把原本真正門派專用任務的公式取消。

---

## 10. 檔名與既有舊檔相容性硬檢

新作／主動重整的劇本：

- [ ] 檔名前綴跟隨底層任務類型，而不是跟隨「有沒有引薦」。

既有舊檔若已使用 `OOTB_門派引薦可重覆任務_...`：

- [ ] 不因本規則更新單獨判定為失敗；不要求只為改名而搬檔。
- [ ] 若日後主動重整其類型／檔名，則按當時底層任務運行類別處理。

---

## 11. 最終可直接交付

最後只看最終 md，GM 必須能直接回答：

`原任務類型／replay_policy｜目標門派｜哪些結局可得引薦｜誰有資格｜還可選甚麼｜誰批准｜為何願意背書｜角色卡如何寫｜引薦能做甚麼／不能做甚麼｜once_per_character 時能否重拿｜repeatable 時何時可在新 game_id 再取｜若是關連節點前作 state 如何影響｜社會名譽仍按哪個原任務類型結算`

只要任何答案仍是「GM 自行決定」「看門派心情」「完成就算入門」「入門失敗就重跑同一篇」「有引薦所以自動變 repeatable／改檔名」，即不通過。
