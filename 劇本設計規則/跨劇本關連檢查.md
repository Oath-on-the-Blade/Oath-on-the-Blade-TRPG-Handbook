# 跨劇本關連檢查

本檔只在最終劇本 md 宣告前傳、後傳、平行、承接、分支、匯流、共享事件、揭曉或其他明確跨劇本關連時執行。

先完成 `檢查.md → 拿手檢查.md → 社會名譽檢查.md → 整備檢查.md`，再用**當前最終劇本 md 作主要交付檢查對象**。既有劇本及 `OOTB_任務_<根任務名>_關連樹目錄.md` 只作一致性／關係證據，不能代替本篇缺少的運行資料。

任一硬檢不通過即不得交付。

---

## 1. 直接來源完整性硬檢

- [ ] 最終劇本有明確列出所有實際直接來源。
- [ ] 若本篇核心前提實際同時依賴兩個或以上樹內任務的專用資料，全部來源均有列出。
- [ ] 沒有把只共享地區、門派、年代或主題的劇本冒充直接來源。
- [ ] 所有直接來源均屬同一棵一般關連樹；沒有跨樹讀取劇本專用 `ending_id`、NPC state、物件去向或局部真相。

**失敗條件**：漏列實際來源、假造關連或跨樹依賴。

### 1A. 關連層與任務類型正交硬檢

跨劇本關連只描述**任務與任務之間的關係**，不是會排斥其他任務定位的互斥分類。逐項檢查：

- [ ] 沒有因本篇是關連節點，便自動把它降格／鎖定成「一般冒險」，或刪除本來由正文因果自然成立的高難度、特殊獎勵、門派專用、門派武學或門派引薦定位。
- [ ] 若本篇同時實際觸發門派武學、入門引薦或其他專項，已照最終 md 同時執行相應設計／檢查模組；沒有以「這是關連任務」作豁免理由。
- [ ] 樹內節點之間**沒有被要求必須同建議等級、同歷練基準 R、同劇本規模、同戰鬥強度或同難度**。若等級／難度相同，是因本身設計自然成立，而不是關連樹硬性配對。
- [ ] 若後作比前作更高階、更低階、更難或更簡單，正文的世界規模、威脅、資源、時間、情報與獎勵仍各自合理；沒有只為「配合前作」硬拉數值。
- [ ] 若作者最終決定不提供門派引薦／武學或不採高難度，理由來自本篇沒有足夠授權、傳承、危機結構或劇情需要；**不是因為關連任務被誤當成禁止這些定位的類型**。
- [ ] 若牽涉戰役或可重覆任務，仍完全遵守其專項連續性、實例化與跨劇本前置隔離；本節不構成任何放寬。

**失敗條件**：把「有跨劇本關連」誤當成與門派引薦、武學任務、高難度或其他可並存定位互斥，或反過來用關連名義繞過戰役／可重覆專項限制。

## 2. 關連樹目錄文檔硬檢

「關連樹目錄」必須是：

`OOTB_任務_<根任務名>_關連樹目錄.md`

它是**Markdown 關係索引文檔，不是資料夾**。

### 2.1 第一份關連任務

若本篇是某個原本獨立根任務的第一份關連任務：

- [ ] 同一 repo 變更已建立上述 `.md` 文檔。
- [ ] 文檔至少列出根任務、第一份關連任務、兩者 `script_id`、直接邊與關連類型。
- [ ] 文檔已記錄目前可知的共同背景基線及必要 branch/state 路由。
- [ ] **沒有**為此建立同名資料夾。
- [ ] **沒有**因建立樹而搬動、複製或重新命名根任務／關連任務檔。

### 2.2 已存在關連樹

若來源已屬一棵樹：

- [ ] 沿用既有穩定 `OOTB_任務_<根任務名>_關連樹目錄.md`。
- [ ] 本篇已加入節點表與關連圖。
- [ ] 本篇所有新直接邊均已加入。
- [ ] 受本篇影響的共同背景、branch-specific state、可累積／互斥 state 及 ending→後續映射已同步更新。
- [ ] 沒有因本篇較早發生、較重要或較適合作 anchor 而重命名舊根目錄文檔。

**失敗條件**：缺目錄文檔、目錄未同步、把目錄做成資料夾、搬檔表示樹成員資格、或擅自換根。

---

## 3. 一樹一目錄文檔硬檢

- [ ] 本篇只屬一份一般關連樹目錄文檔。
- [ ] 同一樹沒有因不同分支另建多份互相競爭的根目錄文檔。
- [ ] 沒有把同一劇本複製到另一棵樹來製造關連。

**失敗條件**：一篇多樹、多份 authoritative 目錄、或靠複製檔案表達關連。

---

## 4. 全樹背景一致性硬檢

依關連樹目錄文檔與直接來源逐項核對：

- [ ] 已確立的客觀事實沒有被本篇無聲 retcon。
- [ ] 本篇若新增更深層揭曉，能與既有直接觀察同時成立。
- [ ] 全樹共同背景與某一 branch-specific 結果有清楚分離。
- [ ] 沒有把某 ending 的死亡、被捕、物權、制度改革、公開責任等偷升格成全樹正史。
- [ ] 新篇的時間線、地理、制度與共享物件沒有與樹內既有固定事實衝突。

**失敗條件**：無解釋改寫既有客觀事實或拼接互不相容背景。

---

## 5. ending／state 分支硬檢

- [ ] 每個會影響本篇的前作 `ending_id`／持久 state 都有可執行效果。
- [ ] 效果明確指出只改變甚麼：態度、准入、情報成本、NPC 狀態、物權、制度、敵方準備等。
- [ ] 不會因讀到某 ending 就順手改寫本篇核心真相，除非該真相本來就是明列的 branch-dependent 內容。
- [ ] 同一 ending 可以開啟多於一份後續；未把「同源分支」自動當成互斥。
- [ ] 真正互斥的後續有具體互斥 state，而非只靠作者意圖。

**失敗條件**：`視前作結果調整` 但無可執行映射、把同 ending 的多後續強制二選一、或漏寫互斥條件。

---

## 6. 多來源 `AND`／`OR`／互斥硬檢

若本篇有兩個或以上直接來源：

- [ ] 已明列來源組合是 `AND`、`OR`、互斥或其他可直接執行的邏輯。
- [ ] `AND` 所需 state 可以在同一 campaign 真正同時成立。
- [ ] `OR` 的每條合法入口都有完整運行資料。
- [ ] 互斥 branch 沒有被硬拼成同一開場背景。
- [ ] 多來源各自提供的專用資料均有清楚 provenance。

**失敗條件**：來源邏輯模糊、條件實際不可同時成立、或合併了互斥 branch。

---

## 7. 無前作紀錄基線硬檢

若本篇標示 `連續性：independent` 且前作不是必要前置：

- [ ] 最終劇本本身有完整無前作紀錄基線。
- [ ] 無前作時不會偷偷指定某一前作 ending 已發生。
- [ ] 必要真相、NPC、線索、場景、結局都不要求 GM 開前作檔補資料。

若前作是必要前置：

- [ ] 正文明列必要前置。
- [ ] 明列接受哪些 `ending_id`／state。
- [ ] 沒有在目錄文檔中自行取消或放寬劇本正文的必要前置。

**失敗條件**：無紀錄時無法運行、偷指定前作正史、或索引與正文前置矛盾。

---

## 8. 跨劇本 NPC 身份硬檢

若本篇使用前作 NPC：

- [ ] 使用 `NPC#前作編號@前作劇名`。
- [ ] 前作編號、身份與既有姓名映射一致。
- [ ] 已讀取死亡、失蹤、離職、被捕、敵對等已保存狀態。
- [ ] 不會因 NPC 不可出場便令必要線索永久斷裂；若不是硬前置，已有替代來源。
- [ ] 若該 NPC 必須存在，本篇的 branch/state 前置有明示。

**失敗條件**：同一人改編號、復活／重置已確立狀態、或唯一必要線索依賴不可保證出場的人物。

---

## 9. 物件／證物／武學來源連續性硬檢

- [ ] 前作物件只在實際仍存在、仍由角色／NPC 持有或可合理調取時帶入。
- [ ] 已交官、毀損、消耗、遺失、轉讓或被奪的物件不會無條件重生。
- [ ] 物權與保管 state 依既有 receipt／ending 帶入。
- [ ] 前作只是傳聞、不完整文本或非正式接觸時，本篇不把它升格成正式武學／特殊獎勵來源。

**失敗條件**：跨篇複製物件、重置物權或偷渡正式獎勵來源。

---

## 10. 當前劇本自足性硬檢

即使本篇有前作：

- [ ] GM 只看本篇最終 md 就能主持本篇必要場景與判定。
- [ ] 前作引用主要用來承接 state，而不是把本篇必要真相外包到前作正文。
- [ ] 關連樹目錄文檔不是玩家必讀資料，也不是本篇缺漏運行資料的替代品。

**失敗條件**：必須打開目錄或前作才能知道本篇必要真相／NPC／線索／結局。

---

## 11. 可重覆來源隔離硬檢

若任一來源是可重覆任務：

- [ ] 已另執行 `可重覆任務檢查.md` 第 9 節。
- [ ] 沒有把某一次 repeatable instance 當成永久必要前置正史，除非另有正式規則允許。

---

## 12. 目錄文檔內容完整性覆檢

在 repo 變更完成後檢查 `OOTB_任務_<根任務名>_關連樹目錄.md`：

- [ ] 根任務與根 `script_id` 正確。
- [ ] 所有已知樹內節點均列出。
- [ ] 直接邊與關連圖一致。
- [ ] 沒有把間接祖先誤寫成直接來源，除非本篇真的直接讀取它。
- [ ] 共同背景與 branch-specific state 分離。
- [ ] many-to-many ending→後續關係沒有被樹狀排版誤寫成互斥。
- [ ] 多來源匯流的 `AND`／`OR`／互斥條件可讀。
- [ ] 目錄沒有創造劇本正文未存在的新 ending、前置、NPC 命運、物權或真相。

---

## 13. 反交付總閘門

以下任一情況即 FAIL：

- 建立了 `OOTB_任務_<根任務名>_關連樹目錄/` 資料夾，而不是 `.md` 關係索引文檔；
- 為建立關連樹而搬動／複製劇本檔；
- 第一份關連任務沒有同時建立目錄文檔；
- 已有樹新增節點但沒有更新目錄文檔；
- 跨樹建立劇本專用直接關連；
- 漏列實際多來源；
- 把互斥 branch 拼在一起；
- 無聲 retcon 全樹共同背景；
- `ending_id`／持久 state 只寫抽象描述，GM 無法執行；
- 跨劇本 NPC、物件、物權或武學來源不一致；
- 把「關連任務」誤當成排斥門派引薦、門派武學、高難度或其他可並存定位的互斥類型，或要求樹內節點必須同等級／同難度；
- 以關連樹目錄或前作代替本篇必要運行資料。

只有全部通過，才可把關連劇本與同步更新的 `OOTB_任務_<根任務名>_關連樹目錄.md` 一起視為可交付 repo 變更。
