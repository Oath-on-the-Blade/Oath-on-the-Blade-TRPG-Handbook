# 跨劇本關連檢查

本文件只在最終劇本宣告與一份或多份既有劇本存在前傳、後傳、平行、承接、共享事件、揭曉或其他跨劇本關連時觸發。

**驗收對象仍只有當前最終劇本 md。** 既有關連劇本與 repo 目錄只作一致性／歸檔對照來源，不在本次驗收中替它們重新判定完成度，也不以作者筆記、腦內原意或額外關連帳補正文缺漏。

任何硬性項目不通過，必須回到當前最終劇本正文或本次應完成的 repo 歸檔修正後重檢；不得以「前作有寫」「GM 應該記得」「這幾篇其實有關但沒列」「同一地區所以算關連」視為通過。

---

## 1. 直接來源與表示完整性

先確認：

- 最終 md 是否明確宣告至少一份直接關連來源；
- 每份直接來源是否有可唯一辨識的劇名，最好同時可核對 `script_id`；
- 每條直接關連是否寫明類型：前傳／後傳／平行／承接／共享事件／其他；
- 是否寫明該來源是不是必要前置；
- 本篇的 `independent`／`continuous` 是否與實際承接方式一致；
- 是否列明本篇的主要關連樹。

若正文實際大量使用另一篇的劇本專用真相、NPC、`ending_id` 或局部世界 state，卻完全沒有把該篇列為直接關連來源，判定 **FAIL**。

---

## 2. 關連樹目錄硬檢

### 2.1 第一個關連任務才建目錄

若來源任務原本沒有任何關連，而本篇正是它的**第一份關連任務**，本次交付必須同時建立：

`_任務_<根任務名>_關連樹目錄/`

並確認：

- 根任務是「首次建立關連時被選作原始延伸基準的既有任務」；
- 根任務與第一份關連任務均歸入該目錄；
- 若搬動根任務造成 repo 內既有明確路徑／相對連結失效，本次變更已同步修正；
- 沒有在尚無關連任務時預先建立空目錄。

該建而未建，或只建立空目錄卻沒有完成任務歸檔，判定 **FAIL**。

### 2.2 已有樹必須沿用穩定根

若來源已位於既有 `_任務_<根任務名>_關連樹目錄/`：

- 本篇若以該樹為主要延伸基準，是否存入同一目錄；
- 是否沒有因新增更早前傳、新分支或新揭曉而另建一個新根目錄；
- 是否沒有只因樹長大便替既有目錄改名。

違反穩定歸檔根，判定 **FAIL**。

### 2.3 每個任務只有一份主要歸檔

確認本篇沒有為了表示多項關連而在兩棵樹各放一份相同劇本檔。若同一劇本存在多份「權威副本」，判定 **FAIL**。

---

## 3. 跨樹關連硬檢

若本篇同時關連另一棵既有關連樹：

- 本篇是否仍只留在自己的主要歸檔樹；
- 是否在本篇「直接關連來源／關連定位」清楚指向另一棵樹的實際相關任務；
- 指向是否足以唯一辨認另一棵樹與節點；
- 是否沒有把兩棵樹強制合併成新目錄；
- 是否沒有因此改寫任一棵樹的既有歸檔根；
- 是否沒有要求另一棵樹只為建立這條邊而複製本篇或全面倒改全部舊劇本。

**跨樹關連只需在實際建立關連的任務中把另一棵樹／相關節點列為直接關連。** 不需要目錄合併或雙邊鏡像檔案。

若以「跨樹」為理由造成搬樹、複製劇本或改根，判定 **FAIL**。

---

## 4. 關連 component 發現硬檢

從本篇主要關連樹開始，先讀同目錄節點，再沿各劇本的直接關連與跨樹指向遞迴建立 component。搜尋時必須同時看：

- 來源劇本自己宣告的前傳／後傳／平行／承接；
- 其他劇本反向指向來源的關連；
- 劇名、`script_id`、`@前作劇名`、關連定位／關聯來源欄位；
- 關連任務指向的其他關連樹。

完成後問：

1. 是否仍有一份已明確與來源相連的劇本完全沒有被納入 component？
2. 是否只沿單向「前作 → 本篇」搜尋，而漏掉旁支、反向或跨樹連結？
3. 是否把單純同地區、同門派、同年代但沒有劇本專用承接的作品誤算入 component？

任一答案顯示 component 範圍錯誤，判定 **FAIL**。

---

## 5. Component 客觀事實一致性硬檢

逐項比較本篇與 component 內實際相關節點的 GM 真相、時間線、NPC、地點、物件與結局。

必須全部成立：

- 本篇沒有把既有劇本已明確成立的客觀責任者改成另一人；
- 沒有把既有明確死亡改成從未死亡，或把既有明確生還改成早已死亡，除非來源本身留有合法 branch；
- 沒有改寫已確立的物件來源、地點結構、事件順序或局部歷史；
- 新揭曉只補充空白、揭露更深層資訊或重解讀人物認知，沒有推翻前作已成立的客觀答案；
- 若 component 中已有不同 branch，本篇按 branch state 處理，而不是任選一個寫成共同歷史。

發現任何無聲 retcon，判定 **FAIL**。

---

## 6. 多項關連宣告完整性硬檢

本規則**不要求**本篇一定有兩個以上直接來源。單一 A → B 可以通過。

但必須問：

> 本篇的核心真相、開場 state、主要 NPC 身份、重要物件去向或主要結局是否實際同時依賴兩份以上既有劇本建立的資料？

若答案是「是」：

- 所有這些既有劇本都必須列為直接關連；
- 各自的關連類型都必須寫清楚；
- 若來自另一棵樹，按第 3 節只增加跨樹指向；
- 不能只標其中一篇為「關聯來源」，把其他篇當成未聲明背景資料。

若答案是「否」，單一直接來源不構成缺陷。

若本篇只因同地區、同門派或同年代而硬加第二、第三條關連，卻沒有任何劇本專用因果／state／人物／物件承接，這些假關連應移除；否則判定 **FAIL**。

---

## 7. 分支 state 與無前作基線硬檢

對每一份有 `ending_id` 或持久 state 的直接來源，逐項檢查：

- 本篇引用的 `ending_id` 是否真實存在於來源劇本；
- 每個 state overlay 是否只在相應角色／該桌紀錄實際存在時套用；
- 是否避免把一個前作結局當成所有桌共同歷史；
- 若本篇是 `independent`，是否有**完全沒有前作紀錄也能直接跑**的開場基線；
- 若沒有可靠歸因到本篇角色／該桌的舊紀錄，是否回到無前作基線；
- 若本篇真的是 `continuous` 且有合法必要前置，是否把必要來源、允許的前作 state、開場時間與帶入資源／狀態寫清楚。

`independent` 劇本沒有無前作基線，或把某一個前作 ending 寫成默認共同歷史，判定 **FAIL**。

---

## 8. Component 不等於玩家履歷硬檢

即使多篇位於同一 component，本篇也不得只因作者知道它們相連，就假定玩家已全部經歷。

檢查：

- 本篇是否只讀取實際可由角色履歷／該桌 save 證明的前作 state；
- 未玩過旁支時，是否仍有完整資訊來源與可運行路徑；
- 玩過其中一篇但沒有玩另一篇時，是否不會出現「GM 必須自行補一個中間歷史」才能開局；
- 多份前作 state 同時存在時，是否已寫明它們各自影響甚麼，且不互相覆蓋成矛盾狀態。

若正文把 component 誤當成一條所有玩家都必然走過的固定戰役線，判定 **FAIL**，除非它其實已按正式戰役規則設計。

---

## 9. 跨劇本 NPC 一致性硬檢

若有任何前作 NPC 再登場：

- 是否依 `設計/交付規格與引用.md` 使用 `NPC#前作編號@前作劇名`；
- 前作 NPC 編號是否真實存在且一致；
- 是否提供前作回憶提示；
- 本篇沒有替同一人物另開新的普通 `<NPC#…>` 身份；
- 若 component 早已建立 provenance alias／遷移對照，本篇是否沿用；
- 若人物狀態會因不同前作 ending 分歧，本篇是否按 state 分支處理姓名、傷勢、立場、死亡／生還與所知資訊。

任何身份鍵、人物生死或前作來源互相打架，判定 **FAIL**。

---

## 10. 前作依賴與本篇完整度硬檢

關連可以增加意義，但不得偷走本篇自己的運行資料。

確認：

- GM 不需要打開前作才能知道本篇的客觀真相；
- 本篇重要 NPC 在當前事件中的認知、目的、數值與下一步已完整寫出；
- 本篇必要線索、場景、危機、終局與結算都在本篇存在；
- 玩家未玩過前作時，不會缺少唯一必要資訊；
- 如果前作只是提供更快識別、額外信任、附加證物、程序便利或情感重量，本篇有獨立替代路徑。

若「前作有寫，所以本篇不重寫」造成 GM 必須跨檔補運行資料，判定 **FAIL**。

---

## 11. 可重覆來源隔離

若任何直接來源是 `replay_policy: repeatable`／`運行類別：可重覆任務`，除本文件外，另執行 `可重覆任務檢查.md` 第 9 節。

本篇不得把某一次 repeatable run 當成唯一必要前置，亦不得依賴某次 run 才生成的 NPC、`variant_id`、`PROP#`、`CLUE#` 或一次性 state 才能開局／通關。component 一致性不會放寬可重覆任務前置隔離。

不通過即 **FAIL**。

---

## 12. 反交付閘門

只拿當前最終劇本 md 作判定，並用既有關連劇本／repo 歸檔作對照，逐項問：

- 若這是根任務第一份關連任務，關連樹目錄是否本次才建立且已完成歸檔？
- 已有樹是否沿用原根與原目錄？
- 跨樹是否只增加任務指向，而沒有合併目錄、改根或複製劇本？
- 單一延伸若只有一條直接關連，是否仍與整個 component 相容？
- 若本篇其實承接多篇，是否全部宣告而沒有假裝只有一個 anchor？
- 是否沒有為追求「多關連」硬造無實質承接的 crossover？
- 是否沒有無聲 retcon？
- 是否沒有把某個 branch ending 偷升格成共同歷史？
- 是否沒有把 component 誤當成玩家必經戰役？
- 是否沒有把必要運行資料留在前作？
- 所有前作 NPC、`ending_id` 與持久 state 是否可核對？
- `independent` 是否有無前作紀錄基線？
- 可重覆來源是否通過前置隔離？

任一項不能由**當前最終 md ＋既有關連劇本／repo 歸檔作對照**直接證明，就判定 **未通過**。

只有全部通過，這份跨劇本關連才可交付。
