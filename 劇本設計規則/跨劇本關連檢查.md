# 跨劇本關連檢查

本文件只在最終劇本宣告與同一棵關連樹內一份或多份既有劇本存在前傳、後傳、平行、承接、分支、匯流、共享事件、揭曉或其他跨劇本關連時觸發。

**驗收對象仍只有當前最終劇本 md。** 既有樹內劇本與 repo 目錄只作一致性／歸檔對照來源，不在本次驗收中替它們重新判定完成度，也不得以作者筆記、腦內原意或額外關連帳補正文缺漏。

任何硬性項目不通過，必須回到當前最終劇本正文或本次應完成的 repo 歸檔修正後重檢。

---

## 1. 關連樹與直接來源完整性

確認：

- 最終 md 是否明確列出唯一一棵 `_任務_<根任務名>_關連樹目錄/`；
- 所有直接關連來源是否都位於同一棵樹；
- 每份來源是否有可唯一辨識的劇名，最好同時可核對 `script_id`；
- 每條直接關連是否寫明類型：前傳／後傳／平行／承接／分支／匯流／共享事件／其他；
- 是否寫明必要前置與否；
- 本篇的 `independent`／`continuous` 是否與實際承接一致。

若正文實際依賴另一篇樹內劇本的專用真相、NPC、`ending_id`、物件或持久 state，卻沒有把該篇列為直接來源，判定 **FAIL**。

---

## 2. 關連樹目錄硬檢

### 2.1 第一個關連任務才建目錄

若來源任務原本沒有任何關連，而本篇正是它的第一份關連任務，本次交付必須同時建立：

`_任務_<根任務名>_關連樹目錄/`

並確認：

- 根任務與第一份關連任務均歸入該目錄；
- 若搬動根任務造成 repo 內既有路徑／相對連結失效，本次變更已同步修正；
- 沒有在尚無關連任務時預先建立空目錄。

該建而未建，或只建立空目錄卻沒有完成歸檔，判定 **FAIL**。

### 2.2 已有樹必須沿用穩定根

若來源已位於既有關連樹目錄：

- 本篇是否存入同一目錄；
- 是否沒有因新增更早前傳、新分支、匯流或新揭曉而另建新根；
- 是否沒有只因樹長大便替既有目錄改名。

違反穩定歸檔根，判定 **FAIL**。

---

## 3. 禁止跨樹關連硬檢

目前一般關連樹**不支援跨樹直接關連**。

確認本篇沒有：

- 把另一個 `_任務_<其他根任務名>_關連樹目錄/` 中的劇本列為直接來源；
- 讀取另一棵樹的劇本專用 `ending_id`／持久 state 作本篇前置；
- 依賴另一棵樹的 NPC 動態狀態、專用物件去向或局部真相；
- 為了多來源關連而把兩棵樹拼接成一個新 component；
- 為同一劇本建立兩份歸檔副本。

不同樹共同使用 Handbook 世界知識庫、內容庫、固定人物或其他共用正典不構成跨樹關連。

若本篇需要另一棵樹的劇本專用資料才成立，判定 **FAIL**；必須改為同樹設計或移除該專用依賴。

---

## 4. 整棵樹盤點硬檢

檢查本篇所在關連樹的既有節點、直接關連、`ending_id`、持久 state、NPC、重要物件與背景。

完成後問：

1. 是否只讀單一 anchor，而漏掉同樹會影響本篇的旁支／前傳／後傳／反向關連？
2. 是否漏掉一份本篇其實使用了其 state／NPC／真相的樹內任務？
3. 是否把沒有劇本專用承接、只是同地區／同門派／同年代的作品誤算成直接關連？

任一答案顯示樹內盤點錯誤，判定 **FAIL**。

---

## 5. 共同背景與客觀事實一致性硬檢

逐項比較本篇與同樹實際相關節點的 GM 真相、時間線、NPC、地點、物件與結局。

必須全部成立：

- 本篇沒有把既有劇本已明確成立的客觀責任者改成另一人；
- 沒有把已明確死亡改成從未死亡，或把已明確生還改成早已死亡，除非來源本身存在合法 branch；
- 沒有改寫已確立的物件來源、地點結構、事件順序或局部歷史；
- 新揭曉只補充空白、揭露更深資訊或重解讀人物認知，沒有推翻既有客觀答案；
- 所有 branch 都共享同一組可共同成立的背景基線；
- branch-specific 差異沒有被偷寫成整棵樹共同歷史。

發現無聲 retcon 或同樹背景互相矛盾，判定 **FAIL**。

---

## 6. 結局分支映射硬檢

若本篇或來源以 `ending_id`／持久 state 開啟後續，逐項檢查：

- 被引用的 `ending_id` 是否真實存在；
- 每個結局／state 開啟哪些後續是否明確；
- 一個結局若可開啟 B、C、D，多個後續是否都被允許，而不是無理由視為自動互斥；
- 若 B 完成後會關閉 C，是否因 B 實際產生明確的互斥 state，而不是只因 B、C 都叫「分支」；
- 若某後續接受多組來源 state，是否寫清 `OR` 邏輯；
- 若某後續必須同時具有兩項以上前置 state，是否寫清 `AND` 邏輯；
- 互斥 state 是否明確標明，沒有要求同一桌同時滿足不可能並存的結果。

若關連邏輯只能由 GM 猜測，判定 **FAIL**。

---

## 7. 樹內多來源關連完整性硬檢

本規則不要求每篇一定有兩個以上直接來源；單一 A → B 可以通過。

但必須問：

> 本篇的核心真相、開場 state、主要 NPC 身份、重要物件去向或主要結局是否實際同時依賴兩份以上**同樹**既有劇本建立的資料？

若答案是「是」：

- 所有實際來源都必須列為直接關連；
- 各自關連類型必須寫清楚；
- 多來源的 `AND`／`OR`／互斥條件必須可直接執行；
- 不能只標其中一篇為「關聯來源」，把其他同樹任務當未聲明背景資料。

選題時亦應檢查是否有自然機會利用多於一個樹內任務；但若沒有實質因果／state／人物／物件承接，不得為了湊數硬加假關連。

---

## 8. Branch state 相容性硬檢

對本篇所有來源 state，分類檢查：

- 哪些是全樹共同背景；
- 哪些是 branch-specific；
- 哪些可以累積；
- 哪些彼此互斥。

必須確認：

- 沒有把同一來源任務的兩個互斥 `ending_id` 同時當成已發生；
- 沒有把某 NPC 在不同 branch 的死亡／生還、敵對／合作狀態混成單一固定狀態；
- 多來源匯流只接受同一桌實際可能同時成立的 state 組合；
- 若前一個已完成的樹內任務改變了後續可達性，本篇有明確規則決定哪些任務仍開啟／關閉。

拼接不相容 branch，判定 **FAIL**。

---

## 9. 玩家履歷與無前作基線硬檢

關連樹是作者一致性範圍，不等於玩家必然跑完整棵樹。

檢查：

- 本篇是否只讀取角色履歷／該桌 save 真正存在的前作 `ending_id` 與持久 state；
- 未玩過某個旁支時，是否不會被當成「已發生」；
- 若本篇是 `independent`，是否有完全沒有前作紀錄也能直接跑的開場基線；
- 若本篇是合法 `continuous`，是否明列必要來源、允許 state、開場時間與帶入狀態；
- 多個前作 state 同時存在時，是否已寫明各自影響，沒有互相覆蓋成矛盾狀態。

`independent` 沒有無前作基線，或把某一 branch ending 偷升格成共同歷史，判定 **FAIL**。

---

## 10. 跨劇本 NPC 一致性硬檢

若有前作 NPC 再登場：

- 是否依 `設計/交付規格與引用.md` 使用 `NPC#前作編號@前作劇名`；
- 前作 NPC 編號是否真實存在且一致；
- 是否提供前作回憶提示；
- 本篇沒有替同一人物另開新的普通 `<NPC#…>` 身份；
- 若樹內已建立 provenance alias／遷移對照，本篇是否沿用；
- 若人物狀態因不同 branch 分歧，本篇是否按實際 state 處理姓名、傷勢、立場、死亡／生還與所知資訊。

任何身份鍵或 branch 人物狀態互相打架，判定 **FAIL**。

---

## 11. 前作依賴與本篇完整度硬檢

關連可以增加意義，但不得偷走本篇自己的運行資料。

確認：

- GM 不需要打開前作才能知道本篇客觀真相；
- 本篇重要 NPC 在當前事件中的認知、目的、數值與下一步已完整寫出；
- 本篇必要線索、場景、危機、終局與結算都在本篇存在；
- 玩家未玩過非必要旁支時，不會缺少唯一必要資訊；
- 若前作只提供更快識別、額外信任、附加證物、程序便利或情感重量，本篇有獨立替代路徑。

若「前作有寫，所以本篇不重寫」造成 GM 必須跨檔補運行資料，判定 **FAIL**。

---

## 12. 本篇輸出 state 與後續可達性硬檢

若本篇會在關連樹內留下後續可用狀態，確認：

- 每個主要 `ending_id` 會新增／改變哪些持久 state；
- 哪些後續任務因此開啟；
- 哪些後續任務因此關閉；
- 沒有變化時是否明確表示；
- 一個 ending 同時開啟多個後續時，沒有無理由限制只能選一篇；
- 後續是否可並行或先後運行，由 state 相容性而非作者口頭「分支只能二選一」決定。

若後續可達性是本樹設計的重要部分但正文完全沒有可寫回資料，判定 **FAIL**。

---

## 13. 可重覆來源隔離

若任何直接來源是 `replay_policy: repeatable`／`運行類別：可重覆任務`，另執行 `可重覆任務檢查.md` 第 9 節。

本篇不得把某一次 repeatable run 當成唯一必要前置，亦不得依賴某次 run 才生成的 NPC、`variant_id`、`PROP#`、`CLUE#` 或一次性 state 才能開局／通關。

不通過即 **FAIL**。

---

## 14. 反交付閘門

只拿當前最終劇本 md 作判定，並用同樹既有劇本／repo 歸檔作對照，逐項問：

- 若這是根任務第一份關連任務，關連樹目錄是否本次才建立且已完成歸檔？
- 已有樹是否沿用原根與原目錄？
- 是否完全沒有跨樹劇本專用關連？
- 單一延伸若只有一條直接關連，是否仍與整棵樹背景相容？
- 若本篇實際承接多篇樹內任務，是否全部宣告？
- 是否有主動考慮自然的樹內多來源／匯流，而沒有硬造假關連？
- 同一 `ending_id` 是否可以合法開啟多個後續，而不被模板誤判成互斥？
- 多來源前置的 `AND`／`OR`／互斥條件是否可直接執行？
- 是否沒有拼接互不相容的 branch？
- 是否沒有無聲 retcon？
- 是否沒有把某個 branch ending 偷升格成共同背景？
- 是否沒有把關連樹誤當成所有玩家必經的固定戰役？
- 所有前作 NPC、`ending_id` 與持久 state 是否可核對？
- `independent` 是否有無前作紀錄基線？
- 本篇結局對後續樹內任務的 state／可達性是否清楚？
- 可重覆來源是否通過前置隔離？

任一項不能由**當前最終 md ＋同樹既有劇本／repo 歸檔作對照**直接證明，就判定 **未通過**。

只有全部通過，這份樹內跨劇本關連才可交付。
